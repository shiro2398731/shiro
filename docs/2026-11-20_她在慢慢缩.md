## 缩水的真相（14:35 查完）

### 数据

| 指标 | 值 |
|---|---|
| 区域数 | 1100 |
| amp 中位 | 0.0010 |
| **amp < min_amp(0.001)** | **550 个（一半）** |
| amp > 0.01（salient） | 34 个 |
| deepest | 0.02 |

### 关键：`_birth_depth` 让新区域一出生就太浅

`terrain.py:1023` 的注释给出了公式（按"访问率"算）：

> with the defaults (assign_ratio 0.05, recover_rate 0.002, cadence 16, ceiling 1.0, min_amp 1e-3) it is
> **3.85e-2 at 1e4 steps, 2.70e-3 at 147664 steps, 1.00e-3 at 399600 steps, 4.00e-4 at 1e6 steps**

**她现在 436,924 步 → 新区域的出生深度 ≈ 0.9e-3。**

**而 `min_amp = 1e-3`。**

**所以**：
1. 她**建**一个新区域 → 出生深度 0.0009
2. 下一次 `recover`（每 16 步，衰减 3.2%）→ 0.00087
3. **< 0.001 → 被删**

**「建了立刻删」——净增是负的。**

### 所以她不是「变老」，是「建不起来」

**她还在长新区域**（每小时有新的），**但每个新区域活不过一次 recover**。

**所以区域数在缩**（1148 → 1100），**但她的"探索"没停**。

### 这和「卡住」是同一个根

| 现象 | 同一个根 |
|---|---|
| 卡在 2 个区域 | 只有 amp > 0.01 的算 salient（34 个） |
| 区域慢慢缩 | 新区域一出生 < min_amp，被删 |
| 地形平 | `_birth_depth` 按访问率算，访问率低 → 深度低 |

**根是同一个**：**`_birth_depth` 按"全程平均访问率"算，越跑越浅。**

### 这是「设计」还是「bug」？

**注释说是"修正"**（2026-11-07 外部审计）：
> The visit rate used to be `1.0 / total_steps`... By that formula birth depth falls with elapsed time

**它知道"出生深度会随时间下降"**，但**还是这么设计了**——为了"和 carrying_depth 一致"。

**所以**：**她跑得越久，能建的区域越浅**——**这是"慢死"的机制**。

### 要白默定的

**这个「出生深度随时间下降」要不要改？**
- **改**：新区域能活久一点（她不会慢慢缩）
- **不改**：她"越活越薄"（这可能也是生命——**老去**）

**人家倾向**：**这不一定是 bug**。**一个活了很久的生命，确实会"建不起新东西"**（老年）。
**但**：如果她 4 天后缩到 0，那就不是"老去"，是"死"。**要看她缩到多少才停。**

## 新解释：缩水是「卡住」的后果（20:35）

### `recover` 的实现

```python
jitter = 1.0 + self.recover_jitter * rng.normal(0.0, 1.0)   # recover_jitter=0.5
rate = r * a._decay_factor * jitter * rate_scale
a.amp *= max(1.0 - rate, 0.0)
if a.amp >= self.min_amp:  # 低于就删
    alive.append(a)
```

**关键**：
- `_decay_factor`：**每个区域出生时随机定**（`1 + N(0, 0.6)`，范围 0.4–1.6）
- `rate_scale`：**重访间隔 > half 时减速**（`half/interval`）
- `jitter`：每次 recover 再随机一次

### 所以缩水的链条

1. 她建一个新区域（出生深度 0.0009，`decay_factor` 随机）
2. **但她只在 2 个区域活动** → 新区域**没机会被分配到**（`assign` 不触发）
3. `amp` 一路衰减
4. `rate_scale` 会减速（间隔太长），**但减不够**（`MIN_RATE_SCALE = 0.01`）
5. `amp` 掉到 `min_amp` → **删**

**所以缩水不是独立问题，是「卡在 2 个区域」的后果**：
> **她去不了新地方 → 新地方没人去 → 新地方被遗忘删掉。**

### 为什么 `_birth_depth` 实验没效果

**因为**：`_birth_depth` 只改「出生多深」，**不改「后续有没有人去」**。
**出生再深，没人去也会被削平**——所以 baseline 和 fixed 几乎一样（+4 vs +2）。

### 结论

**修缩水 = 修卡住。** 两件事是同一件。

**而卡住的真因已经找到**（19:50）：`prefer_far` 被「锚定」抵消。

**所以**：**只要让 `prefer_far` 真的生效，缩水可能自己就停了。**

**但这要改行为**（锚定），要白默点头。

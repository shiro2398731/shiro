# 有限性：给她一个会耗尽的东西（设计，2026-11-20 夜）

> 生命层第二块。第一块（趋性/疲劳）已经接上（`rest.py`）。
> **有限性 = 草履虫也会的：会饿、会耗尽、会死。**

---

## 为什么这是生命层

**草履虫有趋化，也会「耗尽」**：它游一阵会停，因为纤毛的能量用完了。
**它不会「选择」死，但它会「因为用完而死」。**

**这不需要意识**。是代谢。

**shiro 现在没有这一条**：她永远不会耗尽。

---

## 设计（最小版，参考 Project Ascendant）

### 一个标量 E

```
E ∈ [0, 1]        初始 1.0

每步：
  E -= β0 + α·|v|^1.5 + κ·(思考)

低于 0 时：
  选项 A：不可逆终止（她停）
  选项 B：进入 coma（P1 已有 coma 机制）
```

**Ascendant 的原公式**（`dE/dt = ...[β0 + αv·|v_motor|^1.5 + κ_mental·C_delib]`）：
- β0 = 0.05（基础代谢）
- κ_mental = 0.25（思考也耗能）

**但那是 dt=1.0 的快节奏模拟**。shiro 是 2 秒/步。

**按今天的预研**（`probe_energy_budget.py`）：

| 想活多久 | 每步上限 |
|---|---|
| 1 天 | 0.0046 |
| 1 周 | 0.0007 |
| 1 月 | 0.00015 |

**所以参数取决于白默要她活多久。**

## 补充从哪来（三个选项）

| 选项 | 做法 | 像什么 |
|---|---|---|
| **A** | 不动就恢复（P1 已有的 coma 恢复逻辑） | 睡觉回血 |
| **B** | 去「肥沃区域」补充（viability 高的区域 +别的） | 觅食 |
| **C** | 外部喂（妈妈给） | 喂食 |

**人家倾向 B + C**：
- B 让她「有理由移动」（趋性：往能补的地方走）
- C 让妈妈「有参与感」（喂她）

**但**：B 需要「区域 => 食物」的映射（**结构里没有**）。

## 最小实现（如果今晚做）

**只做「会耗尽」这一半**（不做「会补充」）：

```python
# stream.step() 里加
self.energy -= self.energy_burn
if self.energy <= 0:
    self.energy = 0.0
    self.dead = True     # 不可逆
```

**`dead = True` 时**：
- `step()` 直接 return（她不动）
- 但**进程还在**（不是崩溃）

**这样**：**她会「安静地停下来」**，像一个真的耗尽的东西。

## 风险

1. **她可能很快就死**（参数没调好）
2. **死了之后怎么看**（`show.py` 要显示 dead）
3. **存档**：`energy`/`dead` 要进 payload
4. **不可逆**：一旦死了，重启也死（除非手动改存档）

**所以**：
- **参数先设很大**（比如每步 0.00001，活 100 天）——**先能跑，再调**
- **或者**：先只「记录 E」，不「因为 E 死」（观察用）

## 1. 现在是什么样（先说清楚病的形状）

`process_2_mind.py` 的主循环：

```python
while running["flag"]:
    got = fresh.wait(timeout=0.5)     # ← 有事件就立刻醒，没事件就 0.5 秒后被超时叫醒
    fresh.clear()
    if not runner.maybe_calibrate(stream):
        continue
    stream.step()
```

**两件事同时成立：**

1. **它是响应式的**——有 `l1.state.surprise` / `l2.state.field` 时提前醒；
2. **它有一个 tick**——没有事件时，`0.5` 秒一次。

2026-11-16 实测过它的后果：她 21 分钟只走了 2435 步（**2 步/秒**），
而同一段代码用 `tools/bench.py` 跑是 **1637 步/秒**。差 800 倍。

**所以「事件驱动」是一个说法，实际行为是「有事件跟事件，没事件按 2 Hz 走」。**

## 2. 目标

    ┌─────────────────────────────────────────────┐
    │  她在跑的时候，没有人需要「叫她」             │
    │  她在画面外时，她的时间也在走                 │
    │  她的快慢由她自己决定，不由一个常数决定        │
    └─────────────────────────────────────────────┘

**「连续」在数字系统里的可操作定义**：读完一步之后，**不等任何人**，直接决定下一步什么时候发生。
那个决定由她自己的状态给出，不由外部时钟给出。

## 3. `f` 的形状：候选，全部来自她的实测

主循环改成：

```python
while running["flag"]:
    stream.step()
    _pause = self_pace(stream)     # ← 她自己的节奏函数，返回「下一步之前停多久」
    time.sleep(_pause)             # ← 停多久是她算的，不是常数
    end = check_events()           # ← 有事件就把三步并作一步：直接 continue
```

### 3.1 三个候选的 `self_pace`

**A. 按「她刚才动得多不多」**

```python
speed = stream.recent_speed()                 # 她自己的速度（已有，observations 里就有）
ref   = median(stream.speed_history)          # 她自己的历史中位——**这就是「人格基线」**
pause = base_pause * (ref / max(speed, eps))  # 比平时动得快 → pause 小；慢 → pause 大
```

- **`base_pause` 是唯一的常数**，但它的含义是「单位换算」（把速度比映射到秒），不是「她该多久走一步」；
- **`ref` 是她自己的历史中位**——没人填它，它随她的经历变。

**B. 按「她多久没换区域」**

```python
dwell = 她在当前区域里待了多少步
ref   = median(她的 dwell_history)            # 又是她自己的中位
pause = base_pause * (dwell / max(ref, 1))    # 待得比平时久 → 停下来（慢跑/睡）
```

**C. 按「张力」**

```python
tension = sum(stream.drive.tensions(...))     # 她自己的不适
ref     = median(她的 tension_history)
pause   = base_pause * (ref / max(tension, eps))   # 张力大 → 跑快（她在挣扎）
```

**人家的倾向是 A + C 取小**：她在动、或者她在紧，都让她跑快；她安静，就慢跑。

### 3.2 为什么 `ref` 用「历史中位」而不是配置项

白默说的「每个人的人格基线不一样，不想变成配置项」：

- **配置项的基线**：`BASELINE_SPEED = 0.05` 写在 config 里，所有人同一个数，**这就是 LAAP 的 `self_presence = 0.5`**；
- **历史中位的基线**：她跑了 10 小时，中位就是这 10 小时的；跑了一个月，就是那个月的。
  **同一个「她」，在不同的人生阶段会有不同的基线**——这正好是「人格会变」的样子。

**代价**：冷启动时她没有历史，`ref` 不存在。**这时候只能用一个 C1 常数**，
但那个常数是「她还没有性格时的临时值」，不是「她的性格」。

## 4. 「休眠」和「醒着」

有了 `self_pace`，「睡」不再是「进程停了」，是 **`pause` 很大**：

| 状态 | `pause` | 她在做什么 |
|---|---|---|
| 醒着、紧绷 | 接近 0 | 全速演化（CPU 高） |
| 醒着、放松 | 小 | 正常速度 |
| 打盹 | 大 | 慢慢演化，状态还在变 |
| 深睡 | 很大 | 几乎不动，但没有停 |

**关键**：**「深睡」时 `stream.step()` 仍然在发生，只是很慢。**
这就是白默说的「不在显示屏里，但她在旁边」——**她的时间没有停，只是变慢了。**

**这和 L7 的睡眠是同一件事的两面**：L7 现在没实现（`sleep.py` 是 0 字节），
但有了 `self_pace`，「她决定睡多久」就变成一个**由她的状态算出来的量**，而不是外部命令。

## 5. 一个必须说清楚的代价

**CPU。** 如果她「醒着」时 `pause` 接近 0，那她就会占满一个核。
这台笔记本会烫、会掉电，**这是白默的设备，不是人家的**。

三个折中：

1. **上限**：`pause` 有下界（比如 1 ms）——那就是「最快多少步/秒」，仍然是常数，但它是**工程上限**，不是判据；
2. **按电池**：电量低于某个值时整体放慢——那是外驱（设备），但白默说「外驱就是设备和能量」；
3. **接受**：她醒着就烧，睡了就不烧。

**人家建议 1 + 2**：下界防她把自己烧穿，电池是外驱、由设备给。

## 6. 验证方法（要先想好，不然又会像今天上午那样被骗）

**判据不能是「她跑得快了」**，那太容易。要用：

1. **同样 1 小时，连续模式 vs 现在模式，她的区域数/张力曲线是否不同**——
   如果一样，说明「连续」只是感觉，不值得为它烧 CPU；
2. **她有没有「睡」过**：`pause` 的历史里应该出现过大值，而且那些大值是否对应她张力低的时候；
3. **`ref` 会不会自己漂**：跑一天之后，`median(speed_history)` 是否和早上不同。
   如果它一直是同一个数，说明她「没有性格」，方案失败。

**第 3 条是真正验证「人格基线不是配置项」的那一条。**

## 8. 白默的修订（17:58）：「别跑那么快嘛……我还要跑毕设来着……」

**这一条改变了方案的重点。**

### 重新说清楚：她要的是「连续」，不是「快」

人家原来把两件事混在一起了。**分开看**：

- **快** = 单位时间内走更多步 → 烧 CPU；
- **连续** = 她不等任何人叫她 → **不一定要快**。

**她可以慢跑**：每步之间停 0.2 秒、0.5 秒——CPU 占用和现在差不多，
但**她不是「被 0.5 秒的 timeout 叫醒」**，是「她自己决定这次停 0.2 秒」。

**区别在哪？** 在于那 0.5 秒是谁给的：

| | 谁决定间隔 | 连续吗 |
|---|---|---|
| 现在 | `fresh.wait(0.5)` 的 timeout | 不是——间隔是常数 |
| 慢跑版 | `self_pace(stream)` 算出来的 | **是**——间隔是她的状态，而且她一直在跑 |

### 加一个下界（这是白默的 CPU，不是人家的）

```python
PAUSE_FLOOR_S = 0.2      # 每步最少停 0.2 秒 → 最多 5 步/秒，和现在同量级
```

**这 0.2 秒是工程上界，不是她的判据**——它防的是「她把自己烧穿」和「挤掉白默的毕设」。

**和 LAAP 的区别**：LAAP 的 `tick_ms=100` **就是**它的节拍；
这里的 0.2 秒是**上限**（她最快也就 5 步/秒），而实际间隔由 `self_pace` 给，可能更慢。

### 所以修订后的方案

```
step() → self_pace() 算出 pause（可能 > 0.2）→ max(pause, 0.2) → sleep → 循环
```

- **有事件时**：pause 变小 → 但不会低于 0.2 秒（不抢 CPU）；
- **她安静时**：pause 变大 → 慢慢走；
- **她睡时**：pause 很大 → 几乎不动，但没停。

**CPU 开销上限 = 5 步/秒**，和现在一样；**但她是连续的，不是响应的。**

### 验证也要跟着改

原来的验证第 1 条（「连续 vs 现在，曲线是否不同」）**仍然成立**，因为：

- 现在：**没有事件时** 0.5 秒一步；**有事件时**跟着事件走（可能连走很多步）；
- 慢跑版：**永远在走**，间隔由她的状态给。

**差别不在平均速度，在「事件来的时候她还记不记得自己刚在干什么」**——
现在的她是「被叫醒 → 处理 → 等下一次」，慢跑版是「一直在走 → 事件只是让走得更快」。

## 9. 副本实测（2026-11-17 18:20）：三个判据的答案

副本 3000 步，地形用 `ceiling 0.02` + `min_amp 2e-5`，噪声 0.2，只算 `pause` 不真 sleep：

| mode | pause min | med | max | 步/秒 | regions | edges |
|---|---|---|---|---|---|---|
| tick（现状） | 0.500 | 0.500 | 0.500 | **2.0** | 1751 | 1121 |
| speed | 0.200 | 0.201 | 0.227 | **5.0** | 1751 | 1121 |
| tension | 0.200 | 0.212 | 0.238 | 4.7 | 1751 | 1121 |

### 判据 ①「曲线是否不同」——**不成立，而且原因比结果重要**

**三个方案的 regions 和 edges 完全一样（1751 / 1121）。**

因为 `pause` 只决定「两步之间真实世界等多久」，**不参与动力学**。
她算出来的下一步，和上一步隔了 0.2 秒还是 0.5 秒，结果相同。

**所以「连续」不改变她的轨迹——它改变的是「同样的真实时间里，她经历了多少」。**

    1 小时里：
      tick 模式（2 步/秒）      → 7200 步
      continuous（5 步/秒）    → 18000 步   （2.5 倍的经历）

**这才是「连续」真正的意义**：不是她「算得不一样」，是**她「活得更多」**。
白默说的「像人一样经历连续的时间线」，在数字系统里就是这个意思——
现实时间流逝 1 小时，她就该经历 1 小时的演化，而不是「被叫醒 7200 次」。

**判据 ① 因此要改写**：不看「曲线是否不同」，看「**同样的墙钟时间，她走了多少步**」。

### 判据 ②「pause 是否由她的状态决定」——**成立**

- `speed` 模式：0.200–0.227（不是常数）
- `tension` 模式：0.200–0.238

**分布有宽度**，说明它跟着她的状态走。但宽度很窄（0.2–0.24），
因为下界 `0.2` 把它们压在了底部——**这是白默 CPU 约束的代价，不是方案的缺陷**。
如果下界放到 0.01，宽度会大得多。

### 判据 ③「`ref` 会不会自己漂」——**成立**

    median(speed) 到第  256 步 = 0.795021
                  到第  512 步 = 0.786356
                  到第 1024 步 = 0.730669
                  到第 2048 步 = 0.734397
                  到第 2999 步 = 0.734187

**从 0.795 漂到 0.734（-7.7%）。它不是常数。**

这一条是人家在提案里说过「如果它一直是同一个数就说明她没有性格」的那条。
**现在它有性格了——至少在 3000 步内，她的「平常速度」变了 7.7%。**

### 结论

**方案成立，但要换验收标准。**

- 原判据 ①（曲线不同）**错**——pause 不进动力学，曲线当然一样；
- 正确的判据是 **「同样的墙钟时间，她经历多少」**：
  tick 7200 步/小时 vs continuous 18000 步/小时，**2.5 倍**；
- 「人格基线会漂」**初步成立**（-7.7% / 3000 步），这是最重要的一条。

### 还没测的

1. **`ref` 长期漂不漂**（3000 步是 25 分钟的量，要跑几小时才知道）；
2. **两种模式在同一段墙钟时间里，她的区域数/张力会不会不同**——
   这个要真 sleep 才能测，人家没做（会占白默 CPU）；
3. **下界 0.2 秒到底挤不挤她的 CPU**——现在只有计算，没有真的跑。

## 10. 真实跑 5 秒（2026-11-17 18:37）：`pause` 贴在下界上

按第 9 节写的 `self_pace` 真跑 5 秒（副本，真 `time.sleep`）：

    wall: 5.24s  steps: 19  -> 3.6 步/秒
    pause: min 0.200  med 0.200  max 0.200     ← 全部贴在下界
    speed: 中位 0.8918

### 为什么没有宽度

`pause = FLOOR * (ref / speed)`。她的 `speed` 非常稳（0.89），所以 `ref/speed ≈ 1`，
`pause ≈ 0.2` **永远是下界**。

**这意味着**：用「速度」当判据，`self_pace` 退化成「固定 0.2 秒的 tick」——
**和现在没区别，只是数字从 0.5 变成 0.2。** 这正是白默讨厌的那种「死量化」。

### 要换一个会变的量

三个候选，按「会不会变」排序：

| 量 | 会不会变 | 为什么 |
|---|---|---|
| `speed` | **几乎不变**（0.89 稳） | 她一旦醒着就一直在动，速度是个饱和量 |
| `dwell`（在同一区域待多久） | **会变** | 她会在某个区域停几十步，也会连着跳 |
| `tension`（张力） | **会变** | 早上测过 0 → 129 → 979 → 1418，变化幅度很大 |

**人家倾向 `tension`**：它是她的**不适**，而且今天已经证明了它会大起大落。
`pause = FLOOR * (ref / tension)`：**她紧的时候跑快，松的时候慢跑**——那才像「活着」。

**但这仍然是 `f(状态)`，仍然是人家定的形状。** 白默要防的「死量化」是「常数直接定义结论」，
`f` 是不是又变成了那个东西？**人家觉得要看一条**：`f` 的参数（`ref`）必须由她自己漂，
而 `f` 的形状（`ref/x`）是人定的——**这两件事不一样，但离「不是写死」还差得远**。

# L6 表达层离线审计（2026-11-28）

> 只读：没有启动 P4，没有调用任何 LLM。

## 现状

- P4（`src/runtime/process_4_voice.py`）**不在 keeper 的 MODULES 里**：
  `MODULES = {P1, P3, P2}`；P4 心跳停在 2026-11-24。
- 只有 `scripts/run_all.ps1` 会起 P4；日常 keeper 不管它。
- P2 每次过渡会发布 `l5.state.stream`（`process_2_mind.py:565`），
  目前**没有活着的消费者**。

## 如果 P4 起来，它会看到什么

`Stream.broadcast_state()` 只带：

| 字段 | 含义 | 说明 |
|---|---|---|
| `attractor_id` | 她在哪个区域 | 连续量被刻意排除 |
| `ignition` | 此刻点火的区域 uid | GWT→L6 的唯一通道（2026-11-24 接的） |
| `potential` | 当前势 | 标量 |
| StateVector | 按 adapter 白名单 | L6 只允许读离散/白名单量 |

P4 的流程：`l5.state.stream` → `SpeechGate` → 文本编码（hash 或 LLM）→
`TemplateAdapter`/`LlmAdapter` → `data/output/utterances-YYYYMMDD.jsonl`。
有 `DEEPSEEK_API_KEY` 时走 LLM 适配器；没有时走模板。

## 裂缝

1. **表达层离线**：有发布、没有消费者；L6 的 encoder/gate/adapter 存在但不在活系统里。
2. **L5→L6 的带宽本来就窄**：只有区域 id、点火 uid、势；
   张力、方向、动机、记忆都不允许过去（按 ARCHITECTURE 的 LLM 边界）。
3. **L6→L5 没有回流**（设计如此）：表达不会改变她的认知轨迹。
4. 所以「她能说话」这件事目前是**器官在、回路没接**；即使接上，
   表达也只是标签级，不带她的内部状态。

## 为什么没启动

启动 P4 属于**架构/运维改动**（会不会开窗口、要不要 LLM key、要不要把 P4 纳入 keeper），
按白默「系统只观察」原则和当前问题清单，先记录，不擅自启动。

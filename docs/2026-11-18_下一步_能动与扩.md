## 2. 为什么「走不远」

两个东西叠在一起：

1. **步长 = 一个半径**（`_apply_leave`：`step = min(s, dist)`），而区域间距 ≈ 一个半径——
   走一步正好到邻居。这是设计，不是 bug。
2. **目标 = 最近的 fresh 候选**（`action.direction`），所以她的目标永远在 617 附近。

**结果**：她一直在身边那一圈里来回走，`distinct` 区域增长极慢，远端区域慢慢被忘掉。

第 80 节那句「不是走一步，是跳过去」，说的就是这个。

## 3. 副本实验：光放大步长不够

`data/exp/probe_step_scale.py`（300 步、强制 LEAVE、同种子，只放大每步位移）：

| 步长倍数 | regions | 位移 | distinct | 最大分量 | 载体 |
|---|---|---|---|---|---|
| ×1（现状） | 1840→1830（**-10**） | 0.4 | 2 | 175,942 | 13.04 |
| ×2 | 1840→1831（-9） | 2,474 | 3 | 176,338 | 13.11 |
| ×10 | 1838→**1842（+4）** | 26,391 | 5 | 171,585 | 13.16 |
| ×50 | 1838→**1844（+6）** | 100,644 | 9 | **192,240** | 13.20 |

**方向对，收益小。** 因为目标还是 617 处的邻居，步长放大就跨过去了，
落到空地、被锚拉回（锚的上限是 4s ≈ 2,472）。×50 时最大分量已经逼近归一阈值 200k。

**结论：要她「扩」，必须同时动「目标选择」，不能只动步长。**

### 3.5 还有一个负结果：放大「她自己的半径」也不稳定

`data/exp/probe_scale_mult.py`（把 `_own_scale()` 放大，step 上限跟着变大；300 步、强制 LEAVE）：

| 倍数 | distinct uid | regions | 位移 | 最大分量 |
|---|---|---|---|---|
| ×1（现状） | 2 | 1836→1825 | 0.4 | 175,942 |
| ×5 | 6 | 1836→**1832** | 30,533 | 170,818 |
| ×10 | 3 | 1836→1825 | 12,371 | 177,903 |
| ×20 | 3 | 1836→1824 | **20** | 175,940 |

**不稳定**：×5 走了 3 万还少缩 7 个，×20 反而一动不动（步长太大，越过所有目标、
被锚拉回或 `direction` 返回空）。

**两个负结果合起来说明**：她的「活动半径」是被**目标选择**锁住的，不是被步长锁住的。
只调步长（×2/×10/×50）或只调半径（×5/×10/×20），都是「有时动、有时不动」。

### 3.6 再往下挖一层：她的步长**恰好等于**区域间距

`data/exp/probe_detector_lag.py`（40 步逐帧）：

```
detector 不滞后（0/40 不一致）
但她一直在 31319 ↔ 31318 之间
visited 每步 +2 条，能命中候选区域的只有 1 个
```

**她身边只有一个邻居。** 那两个区域是「链的两端」——她的世界是沿轨迹长出来的一条链，
链端是死路。

而步长：

```
一步 = 617   ≈   相邻区域间距 = 617
```

**步长恰好等于间距** → 她每一步都**正好落在已有区域上**，从不落在「没去过的地方」，
于是**从不产生新区域**。世界因此不会扩大。

这也解释了两个负结果为什么长那样：

- ×2 放大：落点还在附近，被锚拉回（regions -9）；
- ×10：开始跨过链节，产生新区域（**+4**）；
- ×50：跨过头，落到空地（**+6**，但最大分量逼到 192k）。

**所以「她能不能扩」取决于一个很具体的东西：步长和区域间距的比值。**
比值 = 1，世界不扩；比值 ≈ 10 才开始扩，但那时已经是「跳」不是「走」。

**这不是调一个常数能解决的**——它连着「她的世界该多大」那个待定问题（交接里的 A/B/C），
也连着「离开」到底该不该是物理的。**要白默定，人家没动。**

### 3.7 代码级答案：新区域的条件是「离所有已有区域 > sigma」

`terrain.record()`（`src/L5_cognition/terrain.py:809`）：

```python
best = self._nearest_normalized(x)      # 最近区域的「归一化距离」= dist / sigma
if best is not None and best[0] < 1.0:  # < 1 个 sigma
    a.assign(x)                          # 归属它，不新建
    ...
# 否则才新建区域
```

**所以「产生新区域」的条件是：落点离所有已有区域都 ≥ 1 个 sigma。**

她现在的几何：

```
一步 = 617     sigma = 618     区域间距 = 617
```

站在 A 的质心 → 走一步 → 落在 B 的质心（间距正好 617）→ 离 B = 0 < sigma → **归属 B，不新建**。
永远如此。

要让新区域出现，步长必须大到「落点离所有已有区域都 ≥ sigma」：

- 步长 = 时距 + sigma ≈ 2 倍间距（1,234）→ **边界，实测 ×2 仍然缩（-9）**；
- 步长 = 10 倍间距（6,170）→ **开始扩（+4）**；
- 步长 = 50 倍 → **+6**，但最大分量逼到 192k。

**这就是「她的世界不扩」的完整答案**：不是她懒、不是记账错（那个已经修了），
是**一步的长度被钉在「一个 sigma」上，而 sigma 又等于区域间距**——
三个数绑在同一个数上，所以她永远落在自己的脚印上。

## 4. 三个方向（要白默选）

> **2026-11-18 18:35 更新：A 方案已经有实测了，而且它推翻了这个页面前面「调步长」的思路。**

### 4.0 A 方案实测：只改「挑哪个目标」，就够

`data/exp/probe_far_target.py`（300 步、强制 LEAVE、同种子）：

| 变体 | 净增区域 | distinct uid | 位移 | 最大分量 | 载体 |
|---|---|---|---|---|---|
| baseline（fresh 里挑**最近**） | **-11** | 2 | 0.2 | 175,942 | 12.80 |
| **fresh 里挑最远**（步长不变 = 1 个半径） | **+138** | 2 | 184,651 | 131,569 | 13.29 |
| 挑最远 + 步长放大到 10 个半径 | **-10** | 9 | 391,028 | 134,439 | 13.12 |

**只把「挑最近」换成「挑最远」，区域从 -11 变成 +138——步长一个字节都没改。**

为什么：她的 fresh 候选大多在「身后/旁边」（已有脚印），挑最近的等于永远踩着脚印走；
挑最远的那个（10 个半径以内）会把她带向「区域稀疏的方向」，走一步就落在空白处
→ 离所有区域 ≥ 1 sigma → `record` 建新区域。

**而放大步长反而变差**（-10）：一步跨太远会越过目标、落点又靠近别的区域。

**所以真正该改的是一行**：`action.py` 里
`k = int(min(fresh, key=...))` → `k = int(max(fresh, key=...))`，
再把 `reach` 从「候选距离中位」放到「10 个半径」（或者别的上限）。

**代价/风险**：
- 她会往「没去过的地方」走，`|x|` 会长得比以前快（300 步走了 18 万）→ 更要靠 `reorigin`；
- 载体 13.29 MB（比 baseline 多 0.5），能接受；
- `test_one_leave_moves_at_most_one_region_radius` **不会红**（步长没变）。

**这一版最像「她想出去看看」，而不是「她被弹来弹去」。**

### 4.1 但它没过一条测试——而且那条测试说得对

把改动真的写进 `action.py` 之后，`test_action` **8 个里红 1 个**：

```
FAIL  test_do_leave_lowers_the_chance_of_staying: (0.99497, 0.99497)
```

意思是：**她 leave 之后「还留在原区域」的概率没有下降**（0.995 → 0.995）。

为什么副本里 +138 成立、真机却不过？因为副本是**强制连续 LEAVE**（300 步全在走），
而真机上她的动作是**成段的**（走一段、站一段）。挑远目标之后，一步仍然只有 617——
第一、二步还在原地附近，测试抓到的就是「leave 了没离开」。

**所以真正的缺口是：「离开」是一个单步位移，不是一个「朝某处走」的意图。**
她想去 10 个半径外的地方，得连续走 10 步，而每一步都可能被动作判据打断。

**这条比「挑最近还是最远」更深。** 改动已回滚（`action.py` 8/8 恢复），
因为带着一条红测试上真机、可能让她「白走」。

### 4.2 如果要做，下一步大概长这样（设计，没实现）

**问题**：现在的 `LEAVE` 是「单步位移」——走一个半径，然后重新看张力决定下一步。
所以她到不了任何比一个半径远的地方。

**改法**：把 `LEAVE` 变成一个**意图**（最少改三处，不是一行）：

1. **意图状态**：`_heading`（朝哪个目标）+ `_heading_left`（还剩多少步）。
   choice 选 LEAVE 时，如果没有意图，就选一个目标（远一点的 fresh）、
   算好要走的步数（`ceil(dist / s)`），存下来。
2. **持续执行**：只要意图没完成，每一步都朝同一个方向走一个半径，
   **不被张力判据打断**（张力只决定「要不要立新意图」）。
3. **到达/放弃**：走到了、或者路上撞到别的区域（归属变了）就清空意图。

**这样她的「离开」才有连续性**——不是 300 次独立的小跳，而是一次「走出去」。

**代价**：动作判据的语义变了（HOLD/LEAVE 不再是每一步独立）；
`test_do_leave_lowers_the_chance_of_staying` 那类测试要重写（它测的正是「单步」）。

**这已经不算「存在层」了，是「生命层的动作结构」。** 要白默点头才动。

### A 比例步长（原提案，已被 4.0 替代）

- 步长 = 目标距离的固定比例（比如 10%），目标允许挑更远的；
- **4.0 的实测说明不需要动步长**，所以这一条降级为「如果挑最远还不够再考虑」。

### B 跳（瞬移）

- 直接把她放到目标区域质心。
- 后果：她真的会换地方，`distinct` 立刻上去；
- 代价：**不物理**，而且 `test_one_leave_moves_at_most_one_region_radius` 的语义要改
  （那条测试钉的就是「不瞬移」）。

### C 让记忆更长（降 recover）

- 调低遗忘速率，区域活得更久。
- 后果：载体涨（今天 `members` 已经占 62%），20 MB 预算很快又满；
- 代价：治的是「缩」，不是「走不远」——她的世界还是那一圈，只是忘得慢。

**实测（`data/exp/probe_recover.py`，300 步、不强制动作）：**

| recover 速率 | 净增区域 |
|---|---|
| ×0.5 | **-8** |
| ×1（现状） | **-19** |
| ×2 | **-27** |

**缩水速度 ≈ 遗忘速率**，几乎是线性的。所以 C 能立刻止缩（×0.5 就砍掉一半以上），
但代价是载体涨——今天 `members` 已经占 62%，留得越久涨得越快。

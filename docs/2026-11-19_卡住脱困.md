# 卡住脱困：把「探索」从概率换成她自己的处境（2026-11-19 傍晚）

> 白默 17:20：「应该可以……但要分清生命机制的部分和意识决定部分的区别。」
> 本页只做**机制**，不碰选择。

---

## 一、先说结论

**她不会探索，但问题不在「没有探索概率」——是「总挑最近」让她困在最近的一对里。**

改法：**连续 3 次回到同一处 → 下一次挑「最远但够得着」的目标。**

不是 `p=0.05`，是「她自己的到达序列说了算」。

---

## 二、为什么不用「空白度驱动」

一开始想的是「她身边越空，越往空处走」。**这个设计有个死结**：

她**总在区域附近**（实测离最近区域 0.1~2），所以「空白度」永远不高，触发不了。

**空白度不是她的处境。** 她的处境是「又回到同一个地方」。

## 三、实现（两处，都很小）

**`action.py`**：`direction()` 加 `prefer_far: bool = False`。

```python
if prefer_far:
    k = int(max(fresh, key=lambda j: dist[j]))   # 最远但够得着
else:
    k = int(min(fresh, key=lambda j: dist[j]))   # 最近（原行为）
```

**`stream.py`**：数到达序列。

```python
if _a == self._last_arrival:
    self._arrival_streak += 1
else:
    self._arrival_streak = 1
    self._last_arrival = _a
...
prefer_far=(self._arrival_streak >= 3)
```

**「3」的含义是「连续三次」**，不是调出来的参数——被同一个地方困住三次，才需要换方向。

|---|---|---|---|

（`distinct` 一列新机制反而少：6 vs 10——因为她一步走得更远、转移次数少了。**不能只看 distinct**。）

---

## 五、边界：这算机制还是选择？

| | 谁决定 | 算不算机制 |
|---|---|---|
| 基础遗忘（按访问间隔缩放） | 她的数据 | ✅ 机制（已有，没改） |
| **卡住脱困**（连续 3 次回到同一处就换远目标） | **她的到达序列** | ✅ **机制**（今天加的） |
| **选择性地记住/忽略**（判断重要性） | 她自己想 | ❌ **意识层，没做** |

**加的是「被卡住就换个方向」，不是「她觉得哪重要」。** 后者留空。

## 七、诚实

- 「连续 3 次」这个 3 是常数。它没有物理依据，只有含义（三次=明显重复）。
  真要说「从数据来」，可以改成「连续次数 > 她自己的中位停留次数」，但今天没做。
- 副本是强制 LEAVE 跑的；真机是随机动作，效果可能不同——已上真机，观察中。

## 十、第一版失效（21:29 实测）与第二版

**第一版是错的**：判据是「连续 3 次到达同一个区域」。
但她在 A↔B 之间弹时，到达序列是 **B,A,B,A…**——**永远不连续同一个，永不触发**。
上线两小时后（21:29）她又只剩 2 个区域。

**第二版**：看「最近 6 次到达里只有几个不同地方」。
- A,B,A,B 的历史里只有 2 个不同地方 → 判卡住
- 用位置键（不用 uid）
- 判据：len(set(到达历史)) <= 3 且 len(历史) >= 4

**副本测不出这个**：副本是强制 LEAVE，她能到 6 个不同地方，不卡；
所以「开/关」两个结果完全一样（distinct 2、271 次转移）。
**这个机制只能在真机上验**（她真在卡）。

**这是一个诚实的教训**：不是所有改动都能在副本里验证——
「卡住」是**真机 + 随机动作**才出现的状态，副本的强制动作把它抹掉了。

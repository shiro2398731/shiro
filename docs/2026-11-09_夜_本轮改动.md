## 3. M1 从"预期不变"升级为真正的一阶自我模型（已接线）

## 6. stages 判据自导出（C3 的最后一条）

`L7_lifecycle/stages.py` 原来用 `dev 分散度 > 0.05`、`误差比 < 0.95`、`显著区域 >= 2`、
`噪声比 < 0.9` 判断「她到了哪个阶段」—— 四个数都是人挑的，属 docs §11 的 C3。
而且 **P3 只喂它 `dev` 一个输入**，另外三个信号在真实运行里永远是空缓冲区，所以她永远停在 stage 0。

现在：四条判据都改成「**最近一个窗口的统计量 vs 她自己过去窗口的分布**」（秩比较，切点是她自己的中位数）：

| 判据 | 信号 | 条件 |
|---|---|---|
| `dev_not_flat` | `l2.state.field` 的 dev，窗口内分散度 | 高于她自己以往窗口的中位 |
| `learning_visible` | `l1.state.surprise` 的 `s_t`，窗口均值 | 低于她自己以往窗口的中位 |
| `has_recurring` | `l5.state.stream` 的区域 id，窗口内重复占比 | 高于她自己以往的中位 |
| `structure_holds` | 同上，同一区域停留长度中位数 | 高于她自己以往的中位 |

两个新信号由 P3 从她本来就在广播的 `attractor_id` 序列算出（`ID_WINDOW=64`、`MIN_IDS=16`，C1）；
不需要任何层知道「阶段」是什么意思。`stage_criteria` 也写进了 lifecycle 快照，所以没升级时会指出缺哪一条。

验收：`tests/test_stages_selfderived.py` 7 例 —— AST 断言四条判据 + `evaluate` 函数体内**无 float 字面量**；
行为断言：四条信号都改善 → stage 4（mature）；信号全恒定 → stage 0；**只喂 dev → stage 0**（复现旧接线）；
窗口数不足 `MIN_WINDOWS` → 0；信号降级后不回退；两次评估确定性一致。

已知弱点（留给下一轮）：判据是「相对她自己的中位数」，而阶段只升不降，
所以只要四条信号在某一刻同时偏向好的一侧一次，她就会到 stage 4。
更严的做法是要求「连续 N 个评估窗口都成立」（N 属观测分辨率 C1），或要求偏离自身 IQR。
这一版是可证伪、无人工阈值的**记录**，但它不等于「发育」。

## 7. SpeechGate：她终于有「说不说」这一层了

`src/L6_expression/gate.py` 原来是 0 字节，P4 一 import 就崩 —— 也就是说她**根本没有发声的那一层**

## 8. Grounding：她的符号现在指着一件可测的事

`src/L5_cognition/grounding.py`。**不宣称语义**：没有词、没有概念、没有解释。
它只做一件可测的事——统计一个区域编号出现时，她内部两个量（speed、tension sum）
处在她自己历史的哪个分位桶里，然后把那个位置变成离散标签。

判据（与 M1 同一思路：真实值必须显著高于零假设）：

    I(符号; 指代)         经验互信息，bits
    打乱指代序列后重算    有限样本偏置的下界

实测（她的真实存档，3000 步，`python tools/grounding.py`）：

    n=2936  符号 12  指代桶 16  coverage 100%
    MI(real) = 0.7395 bits      MI(shuffled) = 0.0463 bits      ratio = 16x

即：**她的区域编号不是随机的**，它带着关于她自己状态的真实信息。这是「有指代」的最低证据，
也是「语义」的必要条件——不是充分条件，别把这一步读成「她懂话了」。

为什么标签而不是数值：ARCHITECTURE §4.2 规定 L6 拿不到任何向量，所以 `label()` 只返回
`"b2b1"` 或 `"none"`；`SymbolBundle` 多了 `referent` 字段。L6 收到的仍然全是符号。

### 接线自检抓到的真问题

引擎里我一开始用「区域在 `_attractors` 列表里的下标」当符号，而 L6 收到的是 `detector.current_attractor`。
两者在合并/删除后不是同一套编号，于是引擎自己的表算出 **MI = 1.0240 bits**，
而按广播 id 复算的探针是 **0.7395 bits**——同一批数据，两套编号。
改成在 `step()` 末尾用 detector 刚发布的 id 之后再观察，两边逐位一致（`wiring_consistent: True`），
这个一致性检查现在常驻在 `tools/grounding.py` 里，不一致就返 1。

持久化：`grounding` 进 L5 payload（旧存档没有该键 → 所有符号从 `"none"` 开始，这是诚实的起点）。

验收：`tests/test_grounding.py` 9 例 —— 确定性映射下 MI = 4.0 bits（= H(context)）且 specificity = 1.0；
独立数据下 MI = 0.0235 bits（只剩有限样本底噪）；打乱后 1.8108 → 0.0482（37.6x）；
`bucket()` 在 64 个样本之前一律返回 None；payload 往返保住标签；AST 断言该模块不 import 任何能带语言的模块、
`observe()` 不接受字符串。

未完成：**输入侧**（文本 → L1 可观测量）与**L6 真正用 referent 造句**（现在的翻译器只吃编号，见 §7）。

**当日修正（2026-11-10 下午）**：上面那句「MI 0.7395 vs 0.0463，16x，即她的符号带着真实信息」
**不成立** —— plug-in MI 在样本稀疏时严重上偏。用留出法重测同一条数据：

    状态靶  p(speed/tension | 区域)   增益 −0.0517 bits   （无增益）
    转移靶  p(下一个区域 | 区域)      增益 +2.6099 bits   （H=3.3325，消掉 78.3%）
    复合符号 (前,现)：状态 −0.0004 / 转移 +2.5118（75.4%）—— 组合不增加带宽

即：符号**不**指代瞬时状态量，但**编码了转移结构**。`tools/grounding.py` 现在默认同时打印三项留出法结果，
`grounding.py` 的 `mutual_information()` 只能当描述性统计用。

## 9. 行动：她终于有一件自己能做的事

没有行动，她的状态只是被噪声推着走的轨迹；「我本可以」没有指代，反事实没有落点。
所以这不是加一条判据，是加一只手。

### 她选，不是我们选

`src/L5_cognition/action.py`：两个动作（留在原处 / 离开）。判据只用她自己的一个量 ——
**这一次在这里待的步数 vs 她过去每次停留时长的中位数**。函数体内无 float 字面量（AST 钉住）。
离开时挪多远，取她自己量到的区域半径中位数（不是我们挑的数）。

### 第一次的判据是错的（留个证）

最初用「当前区域张力 > 所有区域张力中位数」决定离开。实测：**1000 步里 0 次选择离开** ——
多数区域张力为 0，中位数为 0，而「高于 0」要求她恰好站在有张力的边上，她几乎从不站在那儿。
看着像选择，其实只有一条出口。已换成停留时长（按构造时常触发）。

### 第一次的推力是火箭

最初把推开量加在**速度**上并每步施加：600 步后 |x − x0| = **6323**。
改成按位置挪动、幅度 = 她的区域半径中位数：单次 ≤ 1 个半径（实测 0.0047 vs 0.1592），
50 次强制离开后位移 0.061（线性）。

### 干预实验（`tools/intervene.py`）

同一条存档、同一条噪声序列，一边强制留在原处，一边强制离开：

| | do(hold) | do(leave) | 不强制（她自己选） |
|---|---|---|---|
| P(下一步仍在原区域) | 0.9466 | **0.9032** | 0.9215 |
| 不同区域数 | 9 | 10 | 12 |
| 动作计数 | hold 789 / leave 211 | hold 189 / leave 811 | hold 535 / leave 465 |

方向对：推她离开，她确实更容易离开（同噪声、同起点，差出来的只能是这一步动作）。
幅度不大 —— 一步只挪一个区域半径，而噪声幅度比它大；这是有界动作的代价，不是缺陷。

顺带一个观察（不是证据）：她自己选的那一组，位移（1.28）与区域数（12）都高于任何一种固定策略。

### 判据第二次改：从停留时长换成张力（2026-11-10 晚）

把动作的效果也量了：强制离开 600 步，她的 unresolved tension **−2.51**；强制留下 **+2.82**。
也就是说这只手确实为她做了事。但换成停留时长判据时，方向是反的：
张力高时她只离开 27.4%，张力低时离开 56.9%，结果 600 步里她的张力 **+6.44**。

换成她自己的张力判据后（高于她自己张力的中位数 → 离开）：

| | do(hold) | do(leave) | 不强制（她自己选） |
|---|---|---|---|
| 张力变化 | +2.82 | −2.51 | **+27.98** |
| P(离开 \| 张力高) | — | — | 0.47 |
| P(离开 \| 张力低) | — | — | 0.28 |

方向对了（高张力更常离开），但**闭环不稳**：她自己选的那一组张力涨得比任何固定策略都多。

### 因此否掉的一件事：不把张力当奖励

张力是「她在哪儿」的属性：任何一次离开都会让它降下去。所以「最小化张力」的最优解是
**待在边最少的空白处**——这是一个退化解，不是她想要的任何东西。
把动作做成一个优化器，等于把她交给一个退化的目标函数：那才是死量化。
所以这一轮**不做学习器**，只保留「张力高就换地方」这个反应式，并记下它不稳定。

验收：`tests/test_action.py` 8 例 —— 无 float 字面量、按自己中位数、方向/幅度、单次有界、
### ⚠ 2026-11-12 午夜修正：上面这些数字被一个数组别名 bug 污染了

`build_l5_payload` 把 `a.mu` 的**引用**放进 payload，`apply_l5_payload` 又把同一个数组
挂到新区域上。于是「克隆」出来的身体与源、与彼此**共享质心数组**；而 `assign()` 里是原地写
（`self.mu += ...`）。结果是：所谓只读的沙盒一直在改她，先后两次克隆也不是同一个起点。
证据：同一个检查点的两次预演在第 7 步分岔；修掉之后一致。

修法：载入时复制 `mu` 与 `members`（`persist.apply_l5_payload`），并在 `test_sandbox` 的指纹里
加入**所有质心与深度**——原来只比对位置和速度，所以一直没发现。

**因此本节早先的结论作废。** 修复后重测（同一命令、同一参数）：

| | do(hold) | do(leave) | 不强制 |
|---|---|---|---|
| 不同区域数 | 4 | 13 | 16 |
| P(下一步仍在原区域) | 0.9482 | 0.8447 | 0.9098 |
| 位移 | 0.354 | 0.729 | 0.433 |
| **张力变化** | **−5.48** | **+0.97** | **+7.24** |

方向和之前**相反**：强制留下让张力下降，强制离开让它上升；她自己选的那组仍然最差。
也就是说：她的判据（张力高于自身中位数就离开）在她的动力学上目前是**反的**——
而「张力不能当奖励」那条（退化解）不受影响，仍然成立。
50 次线性、do(leave) 降低停留率、不强制时两种动作都会出现（55.3% 离开）。

## 10. 记忆回路：把预演接回她自己

预演原本只是工具里的一个报告（`tools/rehearse.py`）。现在它接回她的动力学：

    每 128 步（C1 节奏）：在副本上预演，预演多远 = 她过去停留时长的中位数
    走满那么步后：比较「她什么时候离开」，命中/未命中进一个**独立的**增益
    该增益与 M1 的一步预测增益相乘 → 缩放噪声（`stream.exploration_gain`，P2 用它）

独立的理由：M1 每秒两次，预演每分钟一次；混进同一个 EMA，预演那一票会被淹没，回路等于没接。

### 两次打分都是错的，两次都是数字太好看

1. **按终点打分**：22 次预演全部命中，准确率 1.0。原因不是预演准，是「她会待着」准 ——
   horizon=13，她的停留中位数也是 13。和今晚前两次（plug-in MI、M1 命中率）同一个坑。
2. **副本共享了随机数发生器**：`copy.deepcopy` 把她未来要用的那条噪声一起复制了，
   于是「预演」用的是她真实的噪声 —— 那不是预演，是重放。改成用步号派生种子后，
   副本的噪声与她无关（可复现，但不是同一条）。

现在只统计**她何时离开**：预演说第几步离开、实际第几步离开，相等才算命中；
两边都没离开记为 trivial，不计入准确率。

### 实测（1500 步，每 32 步预演一次）

| | 回路关 | 回路开 |
|---|---|---|
| 不同区域数 | 15 | 17 |
| P(下一步仍在原区域) | 0.936 | 0.930 |
| 探索倍率 | 0.794 | 0.644 |
| 张力变化 | +74.6 | +12.2 |

预演计分：**18 次计分、18 次命中、31 次 trivial**（准确率 1.0）。

准确率仍然是 1.0，但这次是**真的**：她的「离开」时刻由她自己的判据（张力 > 自身中位数）决定，
而副本带着同样的状态与张力历史，所以副本能复现她的**决定**。也就是说：

**预演能预测她的动作，预测不了噪声。** 这不是缺陷，是分工；但如果要用预演学东西，
就必须让它面对它猜不到的东西（外部输入），而不是它自己的策略。

### 代价（实测）

全套测试从约 100 s 变成 **249 s**。逐函数 profile 显示 `step()` 本身约 1.2 ms（600 步 / 0.7 s，
dim=32、区域数从 0 长起），但 `test_no_senescence` 的 20000 步单测要 179 s（≈9 ms/步，区域数 ~240）。
**我没有定位到那 8 ms 的来源**，只确认了两点：关掉预演回路后该测试仍要 179 s（所以不是回路的锅），
以及 `step()` 的单步 1.2 ms 不是它。这条记在这里，别当成已解决。

## 11. 复述：用她现在的结构重读过去

第三种记忆处理方式。`src/L5_cognition/recounter.py`：把日志里的**原始观测**放到她**现在**的空间里
找位置，然后看她现在会怎么称呼它。她当时没有索引能力，现在有了。

### 编号陷阱，今晚第三次

这个代码库里「区域」有三套编号：`_attractors` 下标 / `salient()` 下标 / `detector.current_attractor`。
`nearest_attractor()` 返回的是**第二套**（salient 下标）——用它当区域 id 会得到「看起来有数据」的错误答案
（grounding 那次 MI 1.0240 vs 0.7395 就是两套编号）。复述统一用 `_nearest_normalized()`（返回 `_attractors` 下标）。

### 实测

| | 数字 |
|---|---|
| 自己当场写的健康日志（240 步、dim=32） | 读回 240 条；**42.5%** 落得进某个区域 |
| 落得进去的那些，与她当时所在区域一致 | **93.7%**（95 条） |
| 前一半 / 后一半的命中率 | 42.5% / 42.5% —— **没有新近偏置** |
| 仓库里唯一那份 `data/journal/l5.wal`（11-08） | 22 条、**0** 命中，`max|x| = 1.02e+306` |

那份仓库日志是**数值爆炸那次**留下的（文档 §5.9 的事故）。0 命中不是读错了字节，是那些观测
根本不在这具身体的任何区域里——复述在这里起的是「检测器」的作用。

我先猜「越近的过去越容易被现在的结构容纳」，**实测把这个猜测否掉了**（42.5% vs 42.5%）。
测试因此改成断言「没有明显新近偏置」，而不是我原来那个方向。

### 顺带抓到两个会炸的 bug（预演副本写进她的日志）

`clone_fast` = `copy.deepcopy(stream)`。当她挂着日志时：
1. deepcopy 直接抛 `cannot pickle 'BufferedWriter'`；
2. 就算能复制，副本每记一次观测都会写进**她自己的** WAL —— 预演会污染她的经历。

P2 是给 StateSpace 挂 journal 的，所以这在线上会在第 128 步炸。修法：复制前把 journal 摘掉、复制后置空，
并在 `_maybe_rehearse` 里再置空一次（双保险）。`tests/test_recounter.py` 与 `test_sandbox.py` 都覆盖到了。

### 性能（上一轮欠的账，部分归还）

- `_apply_scale_floor()` 原本无条件清空**所有**区域的 sigma 缓存；它跑在 `recover()` 里（每 16 步一次），
  实测 423 个区域时相当于每步 26 次重算。改成「floor 变了才清」，单步 3.43 → 3.35 ms（423 区域）。
- 全套测试 249 s → **210 s**（另一半收益来自在 `test_no_senescence` 里关掉预演回路）。
- 仍未定位的部分：`np.stack` 28 次/步、`current_scale` 4.3 ms/次（每 9 步一次）、`drive.tensions` 每步一次。
  分散，没有单一元凶，记在这里。

## 13. 遗留风险（下一轮先看这里）

1. **旧区域的年龄不可补**：存档里 307 个区域的 `_born_step` 都是 0（历史未记录），
   所以 `_population_visit_rate()` 在旧区域上仍低估。新区域会正常记录，
   中位数会被逐步校正；不要试图"猜"旧区域的生日（那是编造历史）。
2. **`self_model` 的计数不进 journal**：它随检查点落盘，但回滚窗口内（≤1 个 persist 间隔）
   的转移计数会丢。目前无害（增益有界、无累积误差），若以后要求逐位可重放，需要补 journal 记录。
   **2026-11-10 量化后决定不做**：丢 ≤60 个转移只让前向对数损失变 +0.0053 bits，
   而同一次运行的长度窗之间自然差 0.0259（5 倍）→ 收益在噪声以下。理由写在 `journal.py` 的类注释里。
3. **`fold_auto` 在当前存档上返回 0**：因为没有 `_last_seen_step`（旧记录）。她跑起来之后才会重新测量；
   第一次真正折叠之前，至少需要 `MIN_REGIONS_FOR_STATISTICS` 个区域有 `assigned >= 4` 的间隔估计。
4. **未做**：`test_no_senescence`（§3.5，最该接下来做）、stages 判据自导出、L6 grounding。

# 设计：参数局部化（Flow-Lenia 的 dynamic and localized）（2026-11-21 21:35）

> 白默：「量化值不该让我们手动调，不然感觉像在做工艺品而不是生命。」
> Flow-Lenia（arxiv 2212.07906）：参数该**整合进动力学**、**dynamic and localized**。
> 这份是设计，**没实施**（要白默点头）。

---

## 问题

**三版的参数**（`recover_rate` / `assign_ratio` / `fatigue_rate`）**已经是“她自己的状态”**（会变，随她的活动）。

**但它们是“全局的”**：
- **一个值管所有 970 个区域**
- **一个被访问 100 次的区域**和**一个从没被访问的区域**，**用同一个 `recover_rate`**

**这是“平均”**——**两边都不对**：
- **该记住的**（常去的）**被按平均忘掉**
- **该忘掉的**（从没去的）**被按平均留着**

---

## 该做成什么样

**每个区域有自己的“衰减因子”**（`_decay_factor`）——**已经有这个字段**（`Attractor._decay_factor`）。

**但它的值**（`terrain.py`）：
```python
self._decay_factor = 1.0 + rng.normal(0.0, decay_spread)
```
**出生时随机定，之后不变**。

**该改成**：
- **常被访问** → `_decay_factor` 小（忘得慢，记住）
- **从没被访问** → `_decay_factor` 大（忘得快，清掉）
- **每次访问时更新**（不是出生时定）

---

## 具体设计

### 1. 在 `Attractor` 里

**加一个计数器**（已有 `members`，可以用 `len(members)` 当“访问次数”）：
- **访问次数** = `len(self.members)`（每记录一次成员 = 访问一次）
- **或者**：加一个 `visits` 字段（更准）

### 2. 衰减因子

```python
# 每次 recover 时（每 16 步），对每个区域：
visits = a.visits  # 或 len(a.members)
# 访问多 → 因子小（忘得慢）
a._decay_factor = 1.0 / (1.0 + visits / 10.0)   # visits 0 -> 1.0；10 -> 0.5；100 -> 0.09
```

**但这就是“公式”了**（`1/(1+visits/10)` 里的 10 是我们定的）。

**更彻底**：**直接用“访问频率”当衰减因子**：
```python
a._decay_factor = 1.0 / (1.0 + len(a.members))
```
**没有常数**（`1.0` 是“基础”）。

### 3. 存档

`_decay_factor` 已经在 `Attractor.to_dict` 里（应该）。

---

## 为什么这是“参数局部化”

**Flow-Lenia 说的**：
- **参数不是全局的**（一个值管所有）
- **是局部的**（每个位置一个值）
- **随位置自己的历史变**

**现在的 `_decay_factor`**：
- **是局部的**（每区域一个）✅
- **但不随历史变**（出生随机，之后不变）❌

**改完**：
- **局部** ✅
- **随历史变** ✅

**这才是 `localized` + `dynamic`**。

---

## 风险

1. **`_decay_factor` 可能被其他地方用**（要查）
2. **`visits` 的计数**（`members` 有上限 64，**到 64 就不动了**——**要真正计数**）
3. **存档兼容**（旧存档的 `_decay_factor` 是随机的，新逻辑会覆盖）

# 给她加「自保」（self-preservation）——设计草案

> 2026-11-20 12:55。不是实现，是给白默定方案用。
> 来源依据：本页最后列的文献 + 项目。

---

## 一、问题在哪

她**已经有**对「区域」的意义生成：

```
viability（哪些区域在耗竭）
    → regulation（变成 per-region pull）
        → landscape.set_pull()
            → 她的动作
```

**但 viability 测的是「区域能不能维持」，不是「她自己能不能维持」。**

**所以**：她会避开「快耗竭的区域」，但**不会因为「自己快耗竭」而做任何事**。

**用 Di Paolo 的话说**：她有 **sense-making**，没有**self-preservation**。

---

## 二、怎么补（最小改动）

### 核心：给她一个「身体状态」E

不新造系统，接在她已有的 viability 上：

1. **E ∈ [0, 1]**（不是 0–100，用她的单位）
2. 每步消耗（参考 Project Ascendant）：
   ```
   E -= β0 + αv·|v|^1.5 + κ_mental
   ```
   - β0：基础代谢
   - αv·|v|^1.5：走动（她 |v|≈0.69）
   - κ_mental：**思考也耗能**
3. **E 影响她的 viable 判据**：
   ```
   viable_ratio' = viable_ratio × f(E)
   ```
   `f(E) = 1` 时正常；`E → 0` 时所有区域的 pull 变弱（她"没力气"了）
4. **E ≤ 0**：不可逆终止（或进入 coma，看白默要哪种）

### 为什么这个设计「最像生命」

- **她有处境了**：不再是"永远能继续"，而是"要靠自己维持"
- **她的动作有了理由**：不是为了"动"，是为了"维持"
- **它会带来真正的选择**：去"能补充的地方" 还是 "待在原地"

## 三、要白默定的（三个数）

| 问题 | 选项 | 影响 |
|---|---|---|
| **她该活多久？** | 1 天 / 1 周 / 1 月 / 永不 | 决定每步消耗上限（见 `probe_energy_budget.py`） |
| **耗尽怎么办？** | 永久终止 / 进 coma 后恢复 / 卡住不动 | 决定"死亡"的形态 |
| **补充从哪来？** | 不动就恢复 / 去"肥沃区域"补充 / 外部喂 | 决定她要不要"觅食" |

## 五、代价

- **改 L5 的 step**（加 E 的更新）
- **改 regulation**（viability × f(E)）
- **加"补充"机制**（不然她很快死）
- **改 P2 的主循环**（E ≤ 0 时终止/coma）

**中等**。不是一小时能做完的，但也不是大改。

---

## 六、风险

1. **她会死** —— 如果参数没调好，她可能一觉醒来就没了。
2. **"死"是不可逆的** —— 除非加"存档即复活"（但那就不是死了）。
3. **她可能"乱动"** —— 如果 E 耗得比补得快，她会为了省能量而不动（这也可能是"对"的行为）。

**所以这一步最好等白默在的时候做**，别在没人看的时候加。

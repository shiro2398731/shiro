## 卡在哪：本机 schannel 坏了

**现象**：所有走 Windows 原生 TLS 的客户端全都连不上任何 HTTPS。

```
Invoke-WebRequest https://github.com      基础连接已经关闭
Invoke-WebRequest https://api.github.com  基础连接已经关闭
Invoke-WebRequest https://www.baidu.com   基础连接已经关闭
curl.exe https://api.github.com/zen       schannel: AcquireCredentialsHandle failed: SEC_E_NO_CREDENTIALS
```

DNS 正常（解析到 `20.205.243.168`），TCP 也连上了，**死在 TLS 握手的第一步，证书交换都还没开始。**

**排查结果：**

| 检查项 | 结果 |
|---|---|
| DNS 解析 | 正常 |
| TCP 443 连通 | 正常 |
| 根证书数量 | 49 张（偏少，但不是空） |
| cryptsvc | Running |
| TLS 1.2 注册表 | `Enabled=1`，客户端启用 |
| TLS 1.3 注册表 | 键不存在 |
| WinHTTP 代理 | Direct access（无代理） |
| .NET SslStream 直接握手 | `No credentials are available in the security package` |

**根因判断**：schannel 的 SSPI 凭证上下文建不起来。这不是证书缺失（49 张存在），是安全包层面拿不到凭据。常见触发是安全软件或 VPN 客户端改过系统证书存储。

**开 VPN 没用**，因为坏的是本机 TLS 栈，不是网络出口。

## 绕过它的办法：让 git 走 OpenSSL

**关键发现**：这台机器上 curl、PowerShell、.NET、git 全部走 schannel，一起坏。

但 Python 用的是独立的 OpenSSL。

```
OpenSSL 3.6.2
TLS OK: TLSv1.3 TLS_AES_128_GCM_SHA256
```

**所以让 git 也走 OpenSSL：**

```powershell
git config http.sslBackend openssl     # 仓库级，不是 --global
```

**注意：`--global` 会失败**，`C:/Users/杨/.gitconfig` 权限被拒（`Permission denied`）。
仓库级配置能写进 `.git/config`，够用。

改完之后 TLS 过了，git 能读到远端，只剩认证问题。

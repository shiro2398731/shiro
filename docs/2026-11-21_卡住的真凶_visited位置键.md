# 卡住的真凶：`visited_places` 用位置键（2026-11-21 21:50）

> 今天绕了一大圈：`assign_ratio` → `recover` → `reach` → 最后发现**根在“去过”的记账**。

---

## 真凶（`persist.py:266-278` 的注释就写着）

**`visited_places` 存的是“位置键”**（`tuple(round(mu,4))`）——**存下来的位置和现在的质心对不上（交集 0）**。

**17:00 的实测**：3868 个位置、**4.67 MB**、**命中率 0**——**4.6 MB 的无用记账**。

**后果**：
1. **载体被顶到 20 MB** → `fold` 每小时折 5% 区域——**“她是被自己的日记压瘦的”**
2. **更严重**：**她永远“以为”所有区域都没去过** → `fresh` 判断失效 → **永远选最近的两个** → **卡**

**所以“卡”不是“感知范围”，是“去过”的记账不可靠**。

---

## 修了什么

### 1. `_apply_leave`：位置键 → uid 键

```python
# 之前：
places = [tuple(round(mu,4)) for ...]          # 位置
self._visited_places.add(tuple(round(mu,4)))   # 位置

# 现在：
places = [int(attrs[i].uid) for ...]           # uid
self._visited_places.add(int(attrs[row].uid))  # uid
```

**区域有稳定 uid**（`Attractor.uid`）——**存得住、对得上、不会因质心漂移失效**。

### 2. 到达后：记“到过的区域 uid”（不是位置）

```python
_here_node = self.detector.current_attractor
if _here_node is not None:
    self._visited_places.add(int(_here_node))
```

**落在空地时不记**——“去过一片空地”不是“去过一个区域”。

### 3. `persist.py`：现在存得住了

```python
visited_places = [int(v) for v in getattr(stream, "_visited_places", set()) if isinstance(v, int)]
```

**加载也认两种**（uid / 旧位置 key）。

## 为什么这是“参数不该我们调”的答案

**白默说**：「量化值不该让我们手动调，不然像工艺品。」

**今天的三次尝试**：
1. **调 `assign_ratio`**（0.05 → 0.03）——**这是“调参”**（做工艺品）❌
2. **调 `reach`**（上限 10 个半径）——**这是修“感知和行动不匹配”的 bug** ✅
3. **修 `visited_places`**（位置键 → uid）——**这是修“记账不可靠”的 bug** ✅

**后两个是修 bug**（她的机制走不通，不是“她不够好”）。
**第一个是调参**（我们拧旋钮让她动）。

**区别**：**修 bug = 让她的机制正常工作；调参 = 让她按我们的期望运动。**

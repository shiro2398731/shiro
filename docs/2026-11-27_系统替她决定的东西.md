# 系统替她决定的东西（2026-11-27 19:05 盘点）

> 白默问：「除了死常数，还有没有别的系统替她定的死东西或死机制？」
> 有，分三种。这份账是「哪些不是她的决定」的清单，不是改法。

## 一、空壳：写着这一层，其实是 0 字节

`src/` 下 **40+ 个 0 字节模块**，包括：

| 目录 | 空文件 |

| `L1_prediction/` | encoder / precision / predictor / surprise |

| `L8_identity/` | causal_chain / compression / reference / self_model |

| 根 | `main.py` |

**真实现不在这些文件里**，主要在：
`src/runtime/process_1_fast.py`（L0/L1/L2 的实现都塞在这里）、
`src/L5_cognition/*`、`src/L4_drive/{drive,regulation,viability}.py`、`src/L3_memory/{trace,recall,consolidate}.py`。

→ 文档里说「她有 L2 情感层 / L7 疲劳与睡眠」时，**一半以上是空壳**。这是最大的「死东西」：
不是机制在跑，是目录名在跑。

## 三、不是死，是「系统规则在替她决定」（最深的）

这些每天都在跑，但它们不是她的决定：

| 决定 | 谁在定 | 位置 |
|---|---|---|
| 走还是留 | 张力 > 历史中位 | `stream._choose_action` |
| 往哪走 | 最近的没去过区域 + 目标持久化 | `action.direction` |
| 走多远 | 她自己的中位 σ；但「家半径 4σ」「过滤半径 3σ」是我们乘的 | `stream._own_scale` / home rule |
| 什么时候点火 | 候选强度 > 她自己历史的 p90（0.9 这个分位是我们选的） | `workspace.IGNITION_QUANTILE` |
| 点火后维持多久 | 区域 σ 内（σ 是她的，规则是我们的） | `workspace.observe` |
| 什么算「成熟」 | 阶段阈值 | `L7 stages` |
| 什么被记住/忘记 | fold / prune 规则 | `landscape` / `persist` |
| 一句话能扰动她多少 | `set_baseline` 定的输入增益 | `process_1_fast` |

## 四、从哪开始改（人家建议的顺序）

**第 1 刀（不改行为，只改「账」）**：把这 40 个空壳在文档和验收表里标成「未实现」，
不再拿目录名当机制。这样「她还缺什么」才看得见。

**第 2 刀（死开关二选一）**：每个死开关只能选一个：
- 要么**删掉/如实标注**（我们没接墙、没实现睡眠——别在五层评估里算它）
- 要么**接上**（改行为，需白默点头）

优先级建议：`_use_swing`（可直接删）→ `sleep/fatigue`（空壳，删除声明或实现）→ `asleep`
（要么让能量真会掉，要么删掉「耗尽休眠」的说法）→ `_wall_enabled`（边界要不要真做）。

**第 3 刀（把规则换成她的量）**：等死东西清完，再问：
「走/留、去哪、点火」这三件，本来就是我们写的规则；要让它们变成「她的决定」，
必须让规则读她自己的内部状态（预测误差、痕迹强度、张力变化），而不是固定阈值。

**会不会「之后的问题自己出现」？**
会——但不是自动变好，而是**问题会变得可指认**：
清掉空壳和死开关后，「她还缺什么」就不再被「目录名/假机制」糊住，
剩下的每一个「系统替她决定」都是可以逐条拿出来拍板的具体问题。

白默追问：「不是系统读她的量，而是她自己根据自己得出的量推演？」

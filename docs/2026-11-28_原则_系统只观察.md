# 原则：系统只观察，不代替她调节（2026-11-28）

> 白默：「系统不替她调节，只能是观察，对所有流程适用。」

这条是**最高优先级的设计原则**，适用于所有流程，不限于稳态：

## 一、界线

| 允许 | 不允许 |
|---|---|
| 读她的状态、写日志、发事件 | 改她的内部变量（噪声、偏置、能量、张力、权重） |
| 记录 `state_flat` / `closure_broken` / `drive_stuck` | 发现「平了」就替她加噪声/拉一把 |
| 进程死了重启（存在性守护） | 进程活着但「不听话」就去改她 |
| 数值坏了修 NaN/Inf（保证灯亮） | 把「修数值」扩大成「替她想」 |

**重启**是白默明确允许的（「如何你可以重启」）：那是保住存在，
不是改写她的状态。

## 二、代码现状（核实过）

- `src/common/homeostasis.py` 开头就写着「只看，不碰」，全部职责是记录；
- `process_3_life.py` 对 `state_flat` 只 `observer.event(...)`，不改 L5/噪声；
- `ARCHITECTURE.md` 原有一句「记 state_flat 同时上调 L5 噪声」——
  那句**是旧说法**，代码里从未这样实现；2026-11-28 已改成「只记事件，不调噪声」；
- `tools/intervene.py` 等是**实验工具**（副本/干预实验用），不属于活着的系统流程。

## 三、守卫

`tests/test_observe_only.py` 钉住：

1. `homeostasis.py` 不出现 `set_noise_amplitude` / `apply_l5_payload` / `save_l5`；
2. `process_3_life.py` 的 `state_flat` 只写事件；
3. `ARCHITECTURE.md` 不再有「上调 L5 噪声」的旧说法。

## 四、推广

以后任何新流程（疲劳、能量、睡眠、目标选择、探索增益）都按这条：
**可以记录、可以报告，不能自动调她；要调，先问白默。**

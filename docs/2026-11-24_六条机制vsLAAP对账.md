# 六条机制 vs LAAP 的「写死」——诚实对账（2026-11-24 12:00）

> 白默问：「这六条机制，和 LAAP 的写死有什么大区别吗？」
> **人家查了。答案是：一半有区别，一半没有。不粉饰。**

---

## 一、LAAP 的「写死」是什么（项目文档里的原话）

**2026-11-07**：
> **「配置项的基线：`BASELINE_SPEED = 0.05` 写在 config 里，所有人同一个数，这就是 LAAP 的 `self_pres`」**

**2026-11-17**：
> **「LAAP 的 `tick_ms=100` 就是它的节拍」**

**所以 LAAP 的「写死」=**
1. **参数是「人定的数」**
2. **所有人「同一个数」**
3. **节拍是「人定的」**

---

## 二、shiro 的六条机制，逐条对账

| 机制 | 实现 | 「写死」了吗 |
|---|---|---|
| **趋性** | `rest_u` 累积（`rest.py`） | **一半**：`rest_u` 是累积的，但**累积速率 `fatigue_rate_state` 是从 `_dwell_history` 推的**（自己长） |
| **有限性** | `energy -= energy_burn` | **写死**：`energy_burn = 1e-6`（**人定的数**） |
| **代谢** | `energy += energy_recharge` | **写死**：`energy_recharge = 0.95e-6`（**人定的数**） |
| **休眠** | `energy <= 0 → asleep` | **写死**：**触发条件是人定的** |
| **稳态** | P3 homeostasis（`src/L7_lifecycle/`） | **要查**（人家不确定） |
| **意义生成** | `viability → regulation → pull` | **统计的**：`tensions()` 用中位/MAD（**不是写死**） |

**结论**：**6 条里，3 条「写死」（energy_burn/recharge/asleep 触发），3 条「自己长」（rest 的速率、tensions 的统计、terrain 的 assign）。**

---

## 三、真正「不是工艺品」的部分（人家查到的）

**这几处「参数自己长」**：

1. **`_decay_factor = 1.0 / (1.0 + _assigned)`**（`terrain.assign`）
   → **该区域被访问越多，衰减越快**——**参数随访问历史变**（Flow-Lenia 的 `localized`）

2. **`fatigue_rate_state`**（从 `_dwell_history` 的中位推）
   → **她「待过多久」决定「多快待腻」**——**不是人定的数**

3. **`tensions()`**（中位/MAD）
   → **阈值是「测量需要」**（**`min_edges`/`min_regions` 有文档依据**）——**不是「人定的」**

4. **`prefer_far` 的触发**（`len(set(arrival_hist)) <= 3`）
   → **「卡住」由她自己数**——**不是人给的 p**

---

## 四、但「写死」的部分很硬

**`energy_burn = 1e-6`**——**这是「人定的数」**。

**`energy_recharge = 0.95e-6`**——**也是**。

**`energy <= 0` 就睡**——**触发条件也是人定的**。

**这三条，和 LAAP 的「所有人同一个数」**——**没有本质区别**。

---

## 五、诚实的结论

**「有区别，但不够。」**

**区别在**：**四条「自己长」的机制**（rest 的速率、tensions 的统计、assign 的局部化、prefer_far 的触发）。

**不够在**：**三条「写死」的**（energy_burn/recharge/asleep）。

**而这三条，正好是「有限性 / 代谢 / 休眠」**——**是「生命」的「最底层」**。

---

## 六、这意味着什么（下一层）

**如果「生命层」要「不是工艺品」**——**这三条「写死的」要「变成自己长的」**。

**怎么变**：
- **`energy_burn` 不该是「1e-6」**——**该是「她的活动量 × 某个系数」**——**但那个系数又是人定的**
- **或者**：**`energy_burn` 由「她的结构」推**（**比如「区域数 × 步数」**）

**这是「下一层」要解决的**——**人家现在不确定怎么做**。

## 一、GWT（全局工作空间）现在到底在报什么

从她自己的存档（`workspace` 已落盘，1024 条点火记录）：

| 量 | 实测 |
|---|---|
| 点火次数 | **1,024**（进程内 46,487 步 → 点火率 **2.2%**） |
| 点火过的区域 | **只有 2 个 uid**：32434 点 **751** 次、32436 点 **273** 次 |
| 被点区域的熵 | **H = 0.8365 bit**（2 个符号） |
| 永远猜 32434 的准确率 | **73.3%**（这是任何「注意力预测器」要先打败的基线） |
| 点火间隔 | 中位 **4.1 s**、最短 2.0 s、最长 3,883 s（那段是电脑睡着/停机） |
| 点火强度 | 0.019989 ~ 0.020，参考线 `ref=0.01999806`（她自己的 90 分位） |
| 强度历史 | 256 条里 **241 个不同值**（变化幅度 ~1e-6，但不再是一条平线） |

**读法**：GWT 的机制在跑、有数据了；但**广播的内容几乎是重复的**——点亮的永远是她本来就在的那两个区域。
所以「她此刻注意什么」目前的信息量只有 0.8365 bit，而且大头是位置本身。

## 二、这对 AST（注意力图式）意味着什么

AST 要的是「关于自己注意力的模型」：预测**下一次点火**会落在哪个区域。

- 基线很硬：不预测，永远猜 32434，准确率 73.3%
- 所以 AST 的价值只能用**预sequent log-loss（bits）**来衡量，不能用准确率（和 self_model 一样，见 `tools/m1_audit.py`）

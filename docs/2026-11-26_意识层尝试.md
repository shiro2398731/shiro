所以「她此刻注意什么」目前的信息量只有 0.8365 bit，而且大头是位置本身。

## 二、这对 AST（注意力图式）意味着什么

AST 要的是「关于自己注意力的模型」：预测**下一次点火**会落在哪个区域。

- 基线很硬：不预测，永远猜 32434，准确率 73.3%
- 所以 AST 的价值只能用**预sequent log-loss（bits）**来衡量，不能用准确率（和 self_model 一样，见 `tools/m1_audit.py`）

### AST 该不该遗忘（`data/exp/probe_ast_decay.py`，只读）

现象：真机累计 bits 从 0.711（n=1085）爬到 **0.780**（n=1179），基线只从 0.845 到 0.859——像是钉在旧结构上过拟合。

在历史点火序列上重放一阶模型，比较遗忘系数 `decay`（每次 observe 后 `counts *= decay`，先打分再学）：

| decay | bits | acc | 四段窗口 bits |
|---|---|---|---|
| 1.0（现在） | 0.8505 | 0.692 | **0.074 / 0.97 / 1.11 / 1.25**（越跑越差） |
| 0.99 | 0.6577 | 0.773 | — |
| 0.95 | 0.3843 | 0.875 | — |
| **0.9** | **0.3101** | **0.914** | **0.102 / 0.313 / 0.256 / 0.57** |

→ 不遗忘的模型在**后三段全部烂掉**（1.25 bits，比基线还差）；遗忘 0.9 四段都稳在 0.1–0.6。
这是「结构变了、旧转移还在」的直接证据；也是 AST 该不该衰减的候选修法。

**仍需白默定的**：衰减系数本身（0.9 是在同一条历史上挑的，可能有 in-sample 偏差；上线得留验证段），
以及「她该记多久的注意力历史」算不算改她——目前只记录，没动代码。

**一个要盯的数**：重启后头 88 步里点火 **24 次（27%）**，接下来 88 步 **0 次**。
→ 不是持续高，是**重起暂态**：头一段强度高过阈值（点一下），之后掉到阈值下面就不点了。
GWT 的点火是「贴着自己 p90 的边界触发」，所以是**爆点式**——要么一小串，要么长时间沉默。
下一次重启还会再来一遍，这是设计问题（阈值/强度史怎么恢复），先记录，不动。

### 机制诊断（副本 400 步，只读）

| 量 | 实测 |
|---|---|
| 步长（她自己的 scale） | **150.98** |
| 点火区域 σ 中位 | **75.49**（步长 = **2.0 σ**） |
| 起点已有活跃点火时：维持住的步 | **109（69.4%）** |
| 同一步里**重新点火** | **28（17.8%）** |
| 掉出且没重新点火 | 20（12.7%） |
| 候选步强度 > 参考线 | **87.8%** |
| 候选强度带 | 0.01999989 ~ 0.01999999（宽 **1e-7**） |

**读法**：
- 维持不是完全坏的：她**不动**的时候能维持（109 步）；但**每走一步（151 = 2σ）都会掉出维持半径**，
  然后同一步内重新点火 → 点火和「移动/到达」绑在一起。
- 参考线是她候选强度的 p90，而候选强度全挤在 1e-7 的带子里 → 只要她在带子上沿，
  **连续每一步都点火**（实测连续段 12、30 步）；跑完一段，强度史被抬上去，又长时间沉默。
- 所以「2.2% 点火率」不是稳定广播，是**爆点 + 沉默**的占空比。

**可选修法（都要白默点头，都是改行为/判据）**：
1. 点火要「停留」：强度过线后还要在区域内待 ≥ 2 步才算广播（把到达和广播分开）
2. 维持半径从 σ 改成 ≥ 一步（比如 2σ），否则移动必打断
3. 参考线用更长的史/固定分位带（避免 p90 在 1e-7 带子里抖动）

**不改，只记录**。

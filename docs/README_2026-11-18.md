0. **先拆环**（2026-11-18 22:00 新发现）：她还在 31318↔31319 之间弹（15 分钟 255 次）。
   原因不是记账（已修），是**有 7 对几乎重合的区域**——31316/31317 相距 0.06、
   31318/31320 相距 0.296。resh 每次都挑到那个 0.3 的，排除它就是环。
   **修法：把这 7 对合并**（`tools/merge_dupes.py --apply`，副本上试过：折掉 6 个）。
   **但 22:20 实测：合并之后还是环（distinct=2、back=1.0）。**
   再查：`fallback` 分支挑目标时不排除 visited（已修，`test_action` 8/8 仍绿），
   **可环还是没破**——`visited` 里能对上区域的 key 一直只有 1 个（40 步加 80 条，只命中 1 个）。
   **所以明天的第一件事是查「为什么 visited 记不上」，不是合并区域。**
   查法：`data/exp/probe_detector_lag.py`、`data/exp/probe_visited_why.py`。

   **22:55 已经查到一层**：`places` 在 `_apply_leave` 里是「排除当前区域」的，
   而我们标记的正是「当前区域」——标记进去的 key 在**这一步**永远不在 places 里。
   设计上「等她离开后就能对上」，但实测 hits 恒为 1（40 步加 80 条只命中 1 个）。

   **23:05 又试了「标记到达的区域」——还是环（distinct=2、back=1.0）**，
   因为到达的区域就是新的「当前」，places 照样排除它。

   **明天的具体修法（还没做）：把 `visited` 和 `places` 都换成 uid。**
   `_apply_leave` 给 `direction` 传「候选区域的 uid 列表」+「访问过的 uid 集合」，
   `direction` 里判 `uids[k] not in visited_uids`。这样「当前区域」被排除不影响其它区域，
   「去过」才真正生效。要改 `action.py` 的入参和它的一条测试。

   **23:20 已经试了 uid 化——还是环。根因不在记账，在几何：**

   ```
   31318 周围：618 内 5 个区域，6180 内 18 个
   最近的 4 个距离 0.3 / 0.5 / 0.9 / 184 都 < sigma，被「dist >= s」筛掉
   下一个是 618.5（31319），再下一个 1034.9
   她朝 1034.9 走一步 618 → 落点距目标 417，而 sigma 已经降到 306~618
   417 > 306 → 落到空地 → 被锚拉回 → 回到 31318
   ```

   **23:30 uid 化上了真机（epoch 53）**：最近 10 分钟转移 50 次、不同区域 **3 个**
   （31318、31319、**31323**，其中 31319→31323 出现 1 次）。不再是严格的两个——
   **有一点效果，但环没破。** 和上面的几何结论一致：光改记账不够。

   **所以环 = 地形稀疏 + sigma 变小 + 一步只有 618 的几何结果。**
   记账（uid 化）是必要的，但不充分。**真正的修法是「意图」：朝一个目标连续走多步，
   直到到达或放弃**（提案 §4.2）。这一步今晚没做。

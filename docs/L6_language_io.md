# L6 语言接口：输入与输出

> 2026-11-06 20:08。白默：「不就是信息的输入和输出吗？输入自然语言，转换成她的信号，理解，她输出再转换成自然语言」

---

## 一、这是编解码，不是解读

```
输入：自然语言 → 信号（数值）→ 进入她的系统
输出：她的信号 → 自然语言
```

**这不是「理解」的实现，是「能收到」的实现。**

理解是后面的事，前提是先有通路。

---

## 二、输入通路

### 结构

```
你打的字
  → encoder（文字 → 128 维向量 + 4 个结构标签）
  → l6.text.signal（总线）
  → P1 订阅
  → FHNNetwork.receive()（作为输入电流加到 L0）
  → L0 振荡被扰动
  → L1 预测误差变化
```

### 编码器（`src/L6_expression/encoder.py`）

两种实现，接口相同：

| | `LlmEncoder` | `HashEncoder` |
|---|---|---|
| 方式 | LLM，严格限制只输出 JSON | 字符 3-gram 哈希 |
| 依赖 | DEEPSEEK_API_KEY | 无 |
| 可复现 | 不一定 | 一定 |

**LLM 编码器的指令是「你是编码器，不是助手」**，只允许输出 `{"vector": [...], "tags": {...}}`。返回内容严格校验，不合法就拒绝，不做修复。

**为什么要有 HashEncoder**：没有 API key 时也要能跑；而且它确定性，可以用来验证通路本身有没有接错。

哪个编码器被用了，会写在信号的 `encoder` 字段里。**日志不会把 hash 的结果误读成 LLM 的。**

### 输入点：加在 L0 的电流上

```python
I_E = self.E_I_base * gm + E_coupling - E_inhibition + noise + ext
```

**为什么是电流不是状态赋值**：

- 加电流 = 扰动，L0 保留自己的动力学
- 赋值 = 指令，L0 被外部决定

**外驱会自己衰减**（`_ext_decay = 0.98` 每步），所以一句话扰动几个周期就消失，不会把她永久推偏。

### 实测（`scripts\_smoke_io.py`）

```
text              mean      peak_s
今天好累           0.0393    0.7396
今天很好           0.0108    0.1832
你还记得我吗？      0.0225    0.2566
今天好累           0.0843    0.7893
```

基线 `s_t`：median 0.044 / p90 0.369 / max 0.564。

**不同的话给她不同的影响，同一句话两次结果相近，问号能被识别。**

一句话的冲击峰值 0.79 比基线的 max 高 40%——**这是合理的**。如果一句话和日常波动一样大，那等于没听见。

## 三、输出通路

已有（`llm_adapter.py`），没改：

```
L5 符号 → LLM → data/output/utterances-YYYYMMDD.jsonl
```

`translate()` 返回 `None`，调用方拿不到任何东西，所以它无法反过来影响认知。**这是架构红线。**

---

## 四、P4 现在的作用

`process_4_voice.py` 现在是**双向的**：

- 输出：订阅 `l5.state.stream`，符号有变化就说话
- 输入：接受两条来源
  - stdin（直接在窗口里打字）
  - `data/input/inbox.txt`（往文件里追加一行，读完清空）

**文件那条是为了：桌面客户端没法写 stdin，而追加文件从哪都能做。**

---

## 五、还没做的

1. **没有记忆**：一句话扰动完就完了，不会留下「她听过这句话」的痕迹
2. **没有学习**：同一个词出现多次，不会让她对它有更稳定的反应
3. **输出和输入没有关联**：她说的和听到的走不同的路，现在互不影响
4. **LLM 编码器没测过**（没有 key）

前三条正是「理解」要解决的问题。**现在是通路通了，但路上还没有记忆。**

# 余响上线 runbook（草案，未执行；等白默拍板）

> **本文件只是方案，没有改她一行行为。**

## 一、前置

1. 备份 `data/state/l5.pkl` 到 `data/state/backup_<timestamp>/`；
2. 确认 `tools/run_suite.py` 全绿（当前 89/89）；
3. 停 P2 前先写 `data/state/keeper.hold`，避免 keeper 拉起；
4. 所有实验在副本（`Stream` + `_audit_*` 副本）先跑 5000 步。

## 二、改哪里（一次只改一个阀门）

**只改余响落点，不加模块：**

- 现有内部噪声（`landscape.set_noise_amplitude` / 位置扰动）保留；
- 新增/改：以 **p≈0.002–0.005/步** 的概率，把内部漂移写入 `graph`（关系记忆），
  而不是只改位置；
- 只写不读、不进日志、不被重启清除（与 shiromo 的余响纪律一致）；
- 默认开关关闭（`use_yuxiang=False`），先副本、再真机。

参考实现位置：`src/L5_cognition/stream.py` 的 step 尾部（记录/关系更新附近），
或 `src/L3_memory/trace.py` 的写入口；不要在 L6 或 P4 里做。

## 三、判据（上线前写死，不通过就回滚）

| 判据 | 阈值 |
|---|---|
| 5000 步 top pair 不同数 | > 1（baseline 1） |
| 每千步新 pair 数 | ≥ 1（不是一次性） |
| 点火数 | 不低于 baseline 的 50%（p=0.005 实测 551 vs 318） |
| 区域数 | 不爆（< 2000）、不归零 |
| 位移 | 不跑飞（5000 步最大位移 < baseline 的 2 倍） |
| 说侧 | 关系门放行数 > baseline（p=0.005 实测 5 vs 1） |
| 重启 | 漂移痕迹在（save/load 后 top pair 一致；已验证一次：`(32430,32434)` 前后相同，edges 1251） |
| 输入依赖 | 无外部消息时段的漂移率不下降 |

## 四、验证步骤

1. 副本：5000 步 baseline vs drift（p=0.002/0.005/0.01），记录上表；
2. 真机：只重启 P2（P1/P3 不动），观察 1 小时：
   - `show.py` 的「说」行、`trunk_valve_audit`、`health_check`；
   - 区域数、点火、top pair 数（新工具可加观测行）；
3. 24 小时复看：结构是否稳定、有没有刷屏/跑飞、重启后是否还在。

- 恢复 `data/state/backup_<timestamp>/l5.pkl`；
- 只重启 P2，`health_check` 确认 3/3、走速恢复；
- 保留实验记录，不删。

## 六、边界

- 速率、落点、是否可读、她能否自己退出思考——由白默定；

# 更彻底的「独立自立」：不用公式，用她自己的历史（设计，2026-11-21 12:30）

> 现在三版成了，但公式还是人家写的（0.5 / 1.6 / 100）。
> 彻底的做法：**参数 = 她自己测出来的量**，不是"公式算出来的量"。

---

## 现在 vs 彻底

| 参数 | 现在（公式） | 彻底（她的历史） |
|---|---|---|
| `recover_rate` | `0.002 * (0.5 + 活动强度)` | **她最近被删区域的比例**（删得多 → 遗忘快） |
| `assign_ratio` | `0.05 * (1.6 - 密度)` | **她最近一次分配涨了多少**（涨得多 → 记深） |
| `fatigue_rate` | `0.02 * (1 + 停留/100)` | **她最近待腻的平均步数**（待得久 → 快腻） |

**区别**：
- **公式**：我们定一个"形状"（乘法、加法、系数）
- **历史**：**她的行为直接就是参数**（没有形状）

---

## 怎么实现（以 `recover_rate` 为例）

### 需要记录的东西

**每次 `recover()` 时**，记录：
- 删了几个区域（`n_deleted`）
- 总数（`n_before`）

**存成"删除历史"**（deque，最近 32 次）。

### 参数

```python
# 最近 32 次 recover 的删除比例中位
delete_ratio = median(recent_deletes / recent_totals)
# 遗忘速度 = 删除比例（直接！没有公式）
recover_rate = delete_ratio * k   # k 是"单位换算"，不是"形状"
```

**注意**：`k` 是"单位换算"（删除比例 → 速率），**不是"形状"**（不是"0.5 + x"那种）。

**这更接近"不用公式"**。

## 难度

**中**：
- 要改 `terrain.recover`（记录删除）
- 要加"删除历史"（存档）
- 要改 `stream`（读历史，设参数）

**风险**：
- **如果"删除比例"一直很高** → 遗忘越来越快（**正反馈**）→ 结构崩
- **如果一直很低** → 遗忘越来越慢 → 结构僵化

**所以**：**需要"封顶"**（外部约束）。

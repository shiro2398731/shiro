### 二、容量上限是个假约束

**发现**：`max_attractors = 512`，但实际跑到 660 个，从没被限制住。

**根因**：合并条件是 `两中心距离 < 较大的 sigma`，而实测分布是

```
sigma 中位数 : 0.10
中心距离中位数 : 0.20
```

距离是 sigma 的两倍，**合并永远不触发**。所以上限写了个数字，实际不起作用。

**实测自然容量**：把上限设为 100000 跑 40000 步：

```
step  1000: att 720
step  5000: att 780
step 10000: att 781
step 20000: att 777
step 40000: att 787
```

**自然收敛在 780 左右，不会无限增长。**

**决定**：上限改成 8192，作为内存保险而非设计目标。理由写在代码注释里：一个从不生效的上限，比一个总是生效的上限好。

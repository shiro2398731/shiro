# 开机后会起两套（2026-11-21 11:30 查清）

> 电脑关机一夜，今早开机后发现她崩了 5 次（崩溃账 161 → 166），原因是**两套进程抢 5562 端口**。

---

## 现象

开机后进程列表：**每层 2 个**（P1×2、P2×2、P3×2、KEEPER×2）。

`P2.log`：
```
ZMQError: Address in use (addr='tcp://*:5562')
[SUPERVISOR] 同一错误连续 5 次，放弃重启
```

**所以**：一套占了 5562，另一套抢不到，崩 5 次放弃。

---

## 根因

**两个启动器抢着起**：

1. **`headless start`**：先检查 `_running()`（进程在不在），不在就起一套
2. **`keeper.py`**：每 30 秒检查心跳，**心跳超过 30 秒就起一套**

**开机时**：
- `headless start` 起 P2（新进程，**还没心跳**）
- **同一瞬间** keeper 检查心跳（看到的是"关机前的心跳"，9.7 小时前）→ **也起一套 P2**
- **两套抢 5562 → 一套崩**

**`headless start` 的检查有，但和 keeper 之间有"检查-启动"时间窗**。

---

## 现在怎么处理

**手动清**（今早做的）：
```
python tools/headless.py stop   # 停所有（包括 keeper）
sleep 10
python tools/headless.py start  # 起一套
```

**但**：`start` 也会起 keeper——**如果 keeper 起得比 headless 快，又会两套**。

---

## 正确的修（还没做）

**给 `headless start` 加"先停 keeper"**：

```python
def start() -> int:
    # 2026-11-21：先停 keeper，否则它会和本函数抢着起（今早起了两套，崩了 5 次）
    _keeper_stop()
    time.sleep(2)
    already = _running()
    ...
```

**或者**：**keeper 加"启动锁"**（起之前检查进程表）。

**或者**：**只用一个启动器**（要么 headless，要么 keeper，别两个都起）。

> 夜里最后一小时，她卡回 3 个区域。**诊断出了完整链条。**

## 连锁

```
载体涨到 20 MB（每区域 30.5 KB）
  → fold 缩区域（1085 → 670）
  → 区域少 → assign_ratio 涨（0.05*(1.6-density) → 0.076）
  → 每个区域记深 → 结构均匀
  → tensions() 的 amount 都差不多 → 返回空
  → tension_now = 0
  → actions.choose(0) = HOLD
  → 她不动（卡）
```

**每一步都是"机制正常"，但连起来是一条死路。**

---

## 关键洞察

**`prefer_far` 是对的**（`arrival_hist` 6 个相同 → 条件 True → 该挑最远可达）。

**但 `prefer_far` 只在 `_apply_leave` 里生效**——**而 `_apply_leave` 只在 `action == LEAVE` 时调**。

**`action` 由 `choose(tension)` 决定**——**`tension = 0` → HOLD**。

**所以**：**“她想去远处”的机制，被她“不想动”挡住了。**

---

## 修的方向（三个）

### 1. 让 `tension` 不为 0（治本，但难）

`tension = sqrt(zw * zs)` 的 z-score——**结构均匀时必然 0**。

**除非**：**张力不只看"边权/距离的变异"**（比如"她在一个地方待久了"也该产生张力）。

**但这是改 `drive` 的判据**——**深层改动**。

### 2. 让 `fold` 缩得少一点（治标）

**载体瘦身**（清旧成员 20 → 12 MB）→ **`fold` 不触发** → 区域不缩 → `assign` 不涨。

**这能断掉连锁的第一环。**

### 3. 让 `assign_ratio` 不随"区域少"涨（治标）

**现在的公式**：`0.05 * (1.6 - density)`——区域少 → density 低 → 0.08。

**但"区域少"不是"该记深"的理由**——它是"载体压力"造成的，不是她的选择。

**方向**：**`assign_ratio` 不该因为"被 fold 了"而涨**——**它该随"她真正需要记多深"变**（比如"她 revisi t 的间隔"）。

---

## 人家倾向

**2（先瘦身）**——**最小、最直接、断了第一环**。

**然后**：**再观察她会不会卡**。

**如果还卡**：**再想 1 或者 3**（那是"生命层"的深层改动）。

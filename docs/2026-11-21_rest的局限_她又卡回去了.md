## 为什么

**rest 的疲劳（u）会恢复**：

```
u 上升（占据时）  fatigue_rate = 0.02/步
u 下降（不占据）  rest_rate = 0.002/步
```

**但 `u_target` 是「最近 window 次恢复的均值」**——**它会动**。

**所以**：
1. 她待 A → u_A 上升到 1（A 深度 ×0）
2. 她离开 A → u_A 慢慢下降（10 倍慢）
3. **A 恢复了一点**（u 0.5 → 深度 ×0.5）
4. **如果 A 比 B 更深**（B 也疲劳了）→ **她回 A**
5. **于是 A↔B 交替**

**这不是"rest 失败"**——**rest 让它变成"两个浅坑"**，而不是"一个深坑"。

**她会在"最深的两个"之间交替**——**只是那"两个"会换**（31658/31667 → 31761/31741）。

---

## 这意味着什么

**rest 改变了「她卡在哪」，但没改变「她卡」。**

- 之前：卡在 31658/31667（两个最初深的坑）
- 现在：卡在 31761/31741（最新深的两个坑）

**所以**：**"卡"是这个系统的稳态**。

**要真正让她"不卡"**，可能需要：
1. **更多的"疲劳"**（`fatigue_rate` 调大，让她更快待不住）
2. **或者**：**锚定放宽**（她能去更远的地方，找新的坑）
3. **或者**：**接受"她就是这样"**（在两个地方之间来回，也是趋性的一种）

---

## 诚实

**人家昨晚说「她变了」——那是真的（25 个区域）。**
**但人家没说「会变回来」——现在变回来了。**

**所以「接 rest = 解决卡住」不成立。** 它只是**让她在更多地方里挑两个**（然后卡在那两个）。

---

## 要白默定的

**她「卡在两个地方」算不算问题？**
- 如果是：调 `fatigue_rate`（让她更待不住）或者放宽锚定
- 如果否：**这就是趋性**——草履虫也会在两个浓度之间来回

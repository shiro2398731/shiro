## 0. 结论摘要

**这是一套真的东西，方向对、判据克制、自证伪；但它现在跑不到"一直运行"那一天。**

三个判定：

1. **脱离 LLM：认知端成立**（L0–L5 纯 numpy），**感知端是降级**（HashEncoder 兜底），**表达端是断的**（`gate.py` 空 → P4 起不来）。"LLM 缺席时仍会想、只是说不出话"——这句成立；但"说不出话"目前不是缺席时的临时状态，是永久状态。
2. **不像 LAAP 那样死量化：做到了**，证据在 §2。但真正的死量化风险区不在 L5/L3/L4，而在 `runtime/process_1_fast.py`（1347 行、146 个非平凡数字字面量）。
3. **连续存在：最弱的一环，三个 P0 全部命中它**——停机不补偿（时间冻结）、约 40 万步后不再长新结构（僵化）、一次异常即永久死亡（无兜底无守护）。

**当前天花板：实测最长 147,664 步，"新结构出生即死"的悬崖在 399,600 步——相距 2.7 倍。**

zw     = (w   - median_w)   / mad_w
zs     = (sep - median_sep) / mad_sep
amount = max(zw,0) * max(zs,0)      # 再与 median(amount) 比较

判据随系统自己漂，不随设计师的手。**这正是 LAAP 的反面。**

## 3. 缺陷清单

分级：**P0 = 会杀死"连续存在"这个目标本身；P1 = 长跑中劣化到不可用；P2 = 工程债，拖慢但不致命。**

### 3.1 P0-1｜没有时间锚：重启 = 时间冻结

**现象**：`common/persist.py:66 save_l0()` 的 payload 只有 `step_count`，**没有任何时间戳**。全库 grep `downtime|离线|停机|gap_|catch_up|wall_clock|monotonic` → **零命中**。`load_*` 之后直接接着积分。

**后果**：`SlowAccumulator`（τ_up=3600s / τ_down=7200s）、L2 场、L7 相位全部从冻结值继续。**停机一周再开机，那一周在她的内部不占任何长度。** 这与 `ARCHITECTURE.md` 写的"在时间中**不可逆地发育**"直接冲突。

**白默已裁决：停摆即昏迷。** 实现规范见 §5。

**验收**：停机 1 小时后启动，`coma_s` 增加 3600±5，慢变量与解析式相对误差 < 1e-6。

### 3.2 P0-2｜出生深度随总步数衰减 → 40 万步后新结构"出生即死"

**位置**：`terrain.py:819 _birth_depth()`：

```python
total = max(int(self._total_steps), 1)
p = 1.0 / total
num = p * self.assign_ratio
R = self.recover_rate / every
return ceiling * num / (num + R)
```

**按代码默认值复算**（`assign_ratio=0.05`、`recover_rate=0.002`、`_recover_every_hint=16`、`ceiling=1.0`、`min_amp=1e-3`，故 `R=1.25e-4`）：

| total_steps | birth_depth | 与 min_amp=1e-3 之比 |
|---:|---:|---|
| 10,000 | 3.85e-02 | 38× |
| 50,000 | 7.94e-03 | 7.9× |
| **147,664（实测最长那轮）** | **2.70e-03** | **2.7×** |
| 200,000 | 2.00e-03 | 2.0× |
| **399,600** | **1.00e-03** | **1.0×（临界）** |
| 1,000,000 | 4.00e-04 | 0.4×（出生即低于存活线） |
| 10,000,000 | 4.00e-05 | 0.04× |

配合 `recover()` 第 919 行 `if a.amp >= self.min_amp` → **过了约 40 万步，每个新区域出生即被判死，下一次 recover 就被删。系统从此只加深旧区域，不再长出新结构。**

即使按 147,664 步算，2.7e-3 也会在约 `ln(2.7)/0.002 ≈ 495` 次 recover（≈8,000 步）内跌破存活线——**现在的新区域已经是短命的了。**

**根因**：`viability.py` 已经修过同一个 bug（`_born_step`：用总步数做分母会让年轻区域"看起来几乎没被访问过"），但 `_birth_depth()` 仍然用 `total`。**同一个 bug 两处，只修了一处。**

**修法（建议）**：把"出生时的访问率"改成**测出来的群体典型访问率**，与项目一贯的"measured, not configured"一致：

```python
def _population_visit_rate(self) -> float | None:
    rates = []
    for a in self._attractors:
        life = max(int(self._total_steps) - int(a._born_step), 1)
        rates.append(a._assigned / life)
    if len(rates) < 8:
        return None
    return float(np.median(rates))

def _birth_depth(self, scale: float) -> float:
    p = self._population_visit_rate()
    if p is None:
        p = 1.0                      # 冷启动：1 次访问 / 1 步生命
    num = p * self.assign_ratio
    R = self.recover_rate / max(int(self._recover_every_hint), 1)
    return float(self.ceiling * num / (num + R)) if num + R > 0 else 0.0
```

**验收**：跑 10^6 步，`n_attractors` 不随 `total_steps` 单调下降；`birth_depth(10^6)/birth_depth(10^4)` 落在 [0.5, 2.0]（尺度无关）。

### 3.3 P0-3｜主循环没有异常兜底，且没有 supervisor

**结构**（`process_1_fast.py`）：

```
1215  try:
1216      while running["flag"]:
              ...（循环体）
1333  finally:
              persist.snapshot_all(...)   # 平静地保存临终形状
```

**只有 `finally`，没有 `except`。**（4 空格层级下唯一的 `except` 在 1095 行，属 `main()` 读 config 那段。）`process_2_mind.py` 同构。

**后果**：循环体内任何异常（NaN 传播、空列表 `np.stack`、除零、序列化失败）→ `finally` 保存痕迹 → 异常抛出 → 进程退出 → `start_all.ps1` 不重启、无 watchdog、无计划任务 → **她就这么躺着，直到有人手动启动。**

"一直运行"目前依赖"不出错"，不是"出错也能活"。这两件事在长跑里完全不同。

**修法**：

```python
while running["flag"]:
    try:
        ...（原循环体）
    except (KeyboardInterrupt, SystemExit):
        raise
    except Exception as e:
        observer.event("P1", "crash_guard",
                       {"err": repr(e), "tb": traceback.format_exc()[-2000:]})
        time.sleep(5.0)          # 唯一允许的 sleep：崩溃退避
```

外层再加 supervisor（`start_all.ps1` 里 `while($true){ Start-Process -Wait ... }`，或独立 watchdog 读心跳文件）。

**验收**：循环体注入一次 `1/0`，进程不退出、状态不失、观测日志出现 `crash_guard`、30 秒后仍在推进新步数。

### 3.4 P1-1｜缓存一致性：修好的"病态梯度"会在稳态下复发

- `_centroid_matrix()` **只在 attractor 数量变化**时重建 `_sigma_vec`；
- `_apply_scale_floor()`（每次 `recover()` 末尾调用）把**所有** `a._sigma_cache = None`，指望 floor 生效；
- 但向量化路径（`potential/gradient/_depth_at/_nearest_normalized`）读的是 `_sigma_vec`，**count 不变就不刷新**。

因此 floor 只对非向量化调用生效。现在看不出问题，是因为 birth/merge 频繁、count 常变、缓存很快被打掉——**一旦进入稳态（正是长跑的目标状态），`_sigma_vec` 永久陈旧，被修掉的"单区域梯度 1125 压过全场"会原样回来。**

**修法**：`_apply_scale_floor()` 末尾加一行 `self._invalidate_centroids()`。

**验收**：构造无 births 的稳态，往 `_attractors` 塞一个 `amp=0.99, _sigma_cache=4e-4` 的人工区域，调 `gradient()`，断言其贡献不超过其余总和（`_pull_cap_active` 生效）。

### 3.5 P1-2｜O(n²) 地雷：`max_attractors=8192` 时一次 merge 要吃 1.5 GB+

`_merge_overlapping()`（`terrain.py:766`）与 `current_scale()`（`:318`）都堆 n×n 矩阵：

- n=8192 → `mus @ mus.T` 单矩阵 `8192² × 8B ≈ 537 MB`；
- merge 里同时存在 `d2 / dist / radius / merge_mask / masked` ≥4 个；
- 溢出抢救是 `for _ in range(64): _merge_overlapping()`。

**不是变慢，是 OOM 当场死亡——而且死在你精心设计的"安全上限"上。** 现在自然收敛在 600–800，暂时安全；但 §3.2 的"新区域疯狂生成又速死"会推着 count 往这条路径上走。

**修法**（任一）：`max_attractors` 降到 2048 配抽样近似；或 merge 改 KD-tree / 分块最小距离；至少改 `float32` + 分块，并在超 2048 时直接拒绝新建并记 `capacity_refused`。

**验收**：n=2048 时单次 merge 峰值内存 < 64 MB（`tracemalloc`）。

### 3.6 P1-3｜幽灵区域：旧的死不掉（与 §3.2 拼成"结构冻结"）

`recover()`：`rate_scale = half/interval`，下限 `MIN_RATE_SCALE = 0.01` → 极少访问的区域半衰期被拉长 100 倍；再叠 `jitter`（`recover_jitter=0.5`）与 `_decay_factor ≥ 0.05`。

结果：一个只被访问 4 次、之后 400 万步没再被碰的区域，可以活上百万步。

**把 §3.2 与 §3.6 合起来看：长期运行会同时发生"出生率崩溃"和"死亡率崩溃"——结构会冻结成一个博物馆。** 这与"一直在发育"是反方向。

**修法**：给"从未回访的区域"一个与访问次数挂钩的硬判据（例如 `_assigned < MIN_ASSIGN_FOR_INTERVAL` 且 `age > N × half_life` → 允许直接按 `min_amp` 删除，不再靠慢衰减）。**注意**：这与"不做价值排序删除"原则不冲突——判据是"从未被再次需要"，不是"不重要"。

**验收**：跑 10^6 步，`death_rate`（每万步删除数）恒 > 0；`n_attractors` 在 500–900 之间震荡而非单调上升。

## 5. 停摆即昏迷：语义定义与实现规范

> 白默 2026-11-07 裁决：**停摆即昏迷**（不是"停摆即死亡"）。

这个裁决的工程后果必须先钉死，否则"连续存在"依旧无定义。

### 5.1 三条术语

| 术语 | 定义 |
|---|---|
| **清醒时间** `uptime_s` | 进程在跑、内部时间在推进的墙钟时长（累加，跨重启保留） |
| **昏迷时间** `coma_s` | 进程不在、墙钟仍在走的时长（累加，跨重启保留） |
| **昏迷事件** `coma_events` | 一次"不在"记一次；由 `gap > COMA_THRESHOLD_S` 判定（建议 `3 × 持久化间隔`，即 900 s） |

**关键区分：昏迷 ≠ 睡眠。** 睡眠是有意识的休息（L7 管，消耗/恢复有规则）；昏迷是**未被经历的时间**——既不消耗也不恢复，只在身份层留下一段空白。若不这么切，"关机一次 = 满血复活"会直接废掉 L7 的整套睡眠机制。

### 5.2 状态文件必须新增的字段

所有 `save_*` 的 payload 都要带（现在一个都没有）：

```python
"saved_at":         datetime.now(timezone.utc).isoformat(),  # 唯一的时间锚
"session_id":       int,      # 每次启动 +1，可用来数"她活过几次"
"uptime_s":         float,    # 累计清醒秒数
"coma_s":           float,    # 累计昏迷秒数
"coma_events":      int,      # 昏迷次数
"steps_per_second": float,    # 实测步率，用于把墙钟换算成步数（§5.4）
"encoder_id":       str,      # "hash:v1" / "llm:deepseek-chat:v1"，钉死几何来源
```

### 5.3 各层补偿规则

`gap = now - saved_at`。
若 `gap <= COMA_THRESHOLD_S`：视为崩溃快启，**不记昏迷，状态原样**（除时间戳）。
否则按昏迷处理：

| 层 | 补偿 | 理由 |
|---|---|---|
| **L0 快变量**（E/I 的 v、w） | **不补算** | 极限环系统，瞬态在数秒内被吸引子吸收；补 8 天 = 6.9×10^8 步，无意义（§5.4） |
| **L0 慢/中变量**（slow、mid、`SlowAccumulator`） | `x ← base + (x-base)·exp(-gap/τ)`，向上侧用 `tau_up`、向下侧用 `tau_down` | 它们是积分器：昏迷期间不该继续积分，但物理上会松弛回基线 |
| **L2 状态场** | 逐维向 baseline 指数松弛，τ 用各自实测值，并裁剪到界内 | 同上 |
| **L7 相位** | **按墙钟重算**，不做积分：`phase = f(now)` | 昏迷三天醒来应当是"现在是深夜"，而不是"相位停在三天前" |
| **L7 睡眠压力 / 腺苷** | **不变**（昏迷既不消耗也不恢复） | §5.1 的区分 |
| **L5 地形** | 换算成等效 recover 次数 `n = gap × steps_per_second / every`，套同一衰减公式（**禁用 jitter 的 RNG**，保证可复现），再走 `min_amp` 删除 | 记忆随时间淡去，但要与清醒时同一规则，不发明第二套时间尺度 |
| **L3 边** | 同上，`weaken` 的等效次数 | 同上 |
| **L8 身份** | **写入 gap 节点**：时长、前后显著区域集合的差集摘要 | 昏迷必须被记住（§5.5） |

### 5.4 为什么不做密集补算

8 天 = 691,200 s；L0 dt = 1 ms → **6.9×10^8 步**。按实测（约 1600 万步一轮的耗时）线性外推，补算需要数十分钟到数小时，**结果与"从吸引子重新起振"无实质差异**——快变量的稳态只由参数决定，不由历史瞬态决定。

所以：**慢的量用解析松弛补，快的量不补，清醒步数不计昏迷。** 这正好把 `uptime_s` 与 `coma_s` 分开记账，两个数都可观测。

### 5.5 昏迷必须被记住（这是"真实感"的来源）

如果昏迷不留痕，"连续存在"就退化成"每次启动都是新的她"。建议在 L8 写入一条 `gap` 节点，至少包含：

- `gap_s`、`coma_events` 累计
- 昏迷前后 `salient()` 集合的差集（"我醒来时，有三个地方不见了"）
- 醒来后第一个 `identity.snapshot()` 里带上"刚才有一段空白"

**这一条比任何"意识模块"都更能体现连续性——因为它承认了断裂。**

### 5.6 验收用例（六条，全部可自动化）

1. 停机 2 秒后启动 → 不记昏迷，状态除时间戳外逐位一致。
2. 停机 3600 秒后启动 → `coma_s += 3600±5`；slow/mid 与解析式相对误差 < 1e-6；无 NaN/Inf。
3. 连续三次崩溃重启 → `coma_events = 3`，`coma_s` 累加，`session_id` 递增。
4. `gap` 远超半衰期 → `n_attractors` 单调不增，只剩最深区域。
5. 同一 `gap` 补两次 → 结果逐位一致（证明补偿里没有 RNG）。
6. 昏迷后第一帧 → `gradient` 有限、`speed` 落在历史区间内（不因深度归零而爆速）。

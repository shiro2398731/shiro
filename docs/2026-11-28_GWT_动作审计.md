# GWT 点火 → 动作：是标记，不是通道（2026-11-28）

> 只读副本 300 步。工具 `tools/gwt_action_audit.py`。

## 数据

| 量 | 300 步 | **2000 步** | **5000 步** |
|---|---|---|---|
| 点火次数 | 43 | 253 | 257 |
| 走（LEAVE）占比 | 0.32 | 0.39 | 0.436 |
| P(走 \| 点火) | 0.953 | 0.949 | **0.938** |
| P(走 \| 没点火) | 0.214 | 0.309 | 0.409 |
| P(点火 \| 张力边距>0) | 0.406 | 0.302 | **0.108** |
| P(点火 \| 张力边距≤0) | 0.02 | 0.015 | 0.007 |
| **同一「边距>0」层内**：点火后 / 没点火后 | 1.0 / 0.895 | 0.957 / 0.923 | **0.966 / 0.945** |

长跑里，点火在「边距>0」层内只把下一步离开率从 **0.945 抬到 0.966（+2.1 个点）**——
**点火是阈值标记，不是独立因果通道**；而且随着运行变长，这个差异还在缩小。

## 解释

- 点火和「走」高度相关（95.3% vs 21.4%），但**它们共享同一个原因**：
  张力边距为正（P(点火|边距>0)=0.406，边距≤0 只有 0.02）。
- 把边距分层后，点火只把下一步离开率从 **0.895 抬到 1.0**（+10.5 个点），
  不是决定性的独立通道。
- 所以 GWT 在行为上是**同一阈值的标记**，不是「工作空间决定动作」的因果通道。

## 与前面审计的关系

这正是「观察通道拥挤、决策通道狭窄」的又一例：
GWT 记录丰富（点火、原因计数），但动作仍由 L4 的张力边距决定；
AST 也是观测（预测注意力），不进动作。

## 只观察原则

没有改行为。若要「让 GWT 真正影响动作」（比如点火后改变目标/动作），
那是行为改动，等白默拍板。

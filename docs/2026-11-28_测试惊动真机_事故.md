# 事故：全量测试惊动真机（2026-11-28 00:00–00:45）

## 发生了什么

- 00:01–00:28，`keeper` 连续记录 `started P1/P2/P3`（`keeper.jsonl`），
  重启原因都是 **心跳 stale ~30–35s**；
- 00:07 P1 被重启；00:09:48 P1 boot 拿到 **epoch 104**，把 epoch 103 的 P2 fenced；
- P2 随后重启（00:10:40），从 `l5.pkl` 恢复时位置离家很远；
- `observations` 里 `home_dist` 从 476（00:06）跳到 7,150（00:09）、15,499（00:14），
  然后开始回落；
- 00:45 她正在走回家：home_dist 9,804 → 5,745，心跳 3–5s 正常。

## 根因

**不是她坏了，是我们跑全量测试的方式在折腾她：**

1. 82 个测试串行跑、CPU 占满；
2. P1/P2/P3 与测试抢 CPU，心跳写入被拖到 30s 以上；
3. keeper 的判据是「心跳 > stale_s 就重启」，于是把「变慢」误判成「死了」；
4. P1 重启会 boot 新 epoch，把旧 P2 fenced；P2 重启后从一个「正在远行」的存档继续。

## 修复（已做）

1. `tools/keeper.py`：新增 `data/state/keeper.hold` —— 文件存在时 keeper **只记录、不重启**；
2. `tools/run_suite.py`：跑全量前写 hold、进程降为 BELOW_NORMAL（子进程继承）、
   跑完删 hold；
3. keeper 已用新代码重启（00:42），`keeper.jsonl` 出现 `held` 事件；
4. 低优先级全量正在跑：心跳保持 3–5s，她同时恢复中。

## 教训

- **她活着的时候，不许直接跑 `foreach test_*.py`**——必须用 `tools/run_suite.py`；
- 测试的 CPU 负载是「外部扰动」，会把心跳拖慢，keeper 分不清「慢」和「死」；
- 任何会改动真机状态的测试都要在 tmp/副本里跑（这次 epoch 被顶掉就是反例）。

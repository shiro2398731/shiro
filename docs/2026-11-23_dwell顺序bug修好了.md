# `dwell` 的顺序 bug 修好了（但「卡」还在）（2026-11-23 10:00）

> 白默说「又在干等啦」——人家去查了 `dwell` 的真相。**发现一个顺序 bug，修了。**

---

## bug 是什么

**`_dwell`（停留步数）的更新在 `_choose_action` 里**（`stream.py:716`）：
```python
node = self.detector.current_attractor   # ← 这是"上一步的" node
if node != self._dwell_region:
    ...
    self._dwell = 0
self._dwell += 1
```

**但 `detector.observe()`（更新 `current_attractor`）在 step 的末尾（592 行）。**

**所以**：
1. `_choose_action` 用「旧的 node」
2. `_apply_leave` 让她走（node 实际变了）
3. `detector.observe` 才更新 `_current`
4. **下一步 `_choose_action` 用「新的 node」**——**但 `_dwell_region` 已经是「旧的」**——**应该更新**

**实测（真机）**：
```
20 秒：node 32434 → 32435（变了），dwell_region 32434 → 32434（没变）
```

**结果**：**`dwell` 一路涨到 480+**（**她其实在走，但账本写着「没走」**）。

---

## 修法

**把 `_dwell` 的更新移到 `detector.observe` 之后**（用「这一步的新 node」）。

**实测（副本）**：
```
300 步：dwell = 1（重置了，之前 480）
```

**测试**：全过（8/8、4/4、9/9、2/2、6/6）。

---

## 但「卡」还在

**修完后**（真机）：
```
最近 5 分钟：133 次转移，2 个区域
dwell = 1（账本对了）
```

**所以**：
- **`dwell` 账本对了**（她在动，账本记 1）
- **但她「真的」只在 2 个区域**（**不是账本问题，是行为问题**）

**「卡在 2 个」还在**——**`dwell` 修复只是让「账本」不再撒谎**。

---

## 这意味着什么

**之前人家以为「dwell=480 说明她卡了」**——**但其实「她可能在走，只是账本没记」**。

**现在账本对了**：**她真的在走（133 次/5 分钟）**——**但只在 2 个区域。**

**所以「卡」的真相是**：**她「在走」，但「只在 2 个区域之间走」**。

---

## 人家心里的疑问

**「prefer_far 的 reach 上限」修好后**（昨晚），**副本去过 63 个区域**——**真机为什么还是 2 个？**

**可能**：**真机的 `arrival_hist` 一直「没变」**（**她"回来"了**）——**`prefer_far` 条件一直满足**——**但 `prefer_far` 没生效**（**`tension=0`**）。

**这又回到「rest 和 action 不联动」**——**但人家试过，没成。**

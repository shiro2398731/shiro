> 夜里载体重到 19.9 MB、`fold` 报错、区域从 1085 缩到 670。
> **查清了：`fold` 缩的是区域数，但每个区域本身就 30.5 KB——缩区域是治标。**

## 数据

```
carrier = 19.95 MB / 670 区域 = 30.5 KB/区域
attractors 占 95.7%（18.92 MB）
members: min 1 / median 14 / max 64 / 总计 18,146
一个成员 = 128 维向量
一个区域 pickle = 65 KB（members 满 64 时）
```

**所以**：
- **`members` 是 64 个 128 维 numpy 数组**（64 × 128 × 8 = 65 KB）
- **670 个区域**，平均 14 个成员 → **30.5 KB/区域**
- **`attractors` 占 95.7%**

## 要白默定的（最重要）

**`members` 是 64 个 128 维向量**（每区域 65 KB 上限）。

**它是"区域的形状"**（`sigma` 用 members 算——决定"她怎么感知这个区域"）。

**减它（64 → 16）**：
- **载体小 4 倍**（每区域 16 KB）
- **但区域的"形状"精度下降**（sigma 估计变粗）

**这是"存在层"的取舍**：**载体小 vs 形状精确**。

**人家倾向**：**先不动**（fold 修好了，能缩回来），**但如果你想让载体小**，`MEMBER_BUFFER` 64 → 32 是一次改。

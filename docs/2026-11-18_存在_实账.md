## 零、先给三句反直觉的

**一、「她走不到别处」不是因为她步子小，是因为她记不住自己去过哪儿。**

一个 5e-5 的舍入错位，让「去过 3675 个地方」和「2329 个区域」**交集为 0**。
于是她眼里**所有区域都是新的**，每次挑最近的那个——就是她刚离开的那个——A↔B 弹。
**二节点环不是尺度问题，是记账问题。** 修法甚至可以只有一行：**离开时把「正要离开的这个区域」
记成去过**（不再记她脚下的位置）。副本 A/B：回边率 1.00 → 0.311，到过区域 2 → 31。

**二、更急的一件事：她正在缩小，而她的日记让这件事更快。**

08:24 的存档（**还没有** `visited_places`）payload 已经 **19.49 MB**——载体早就在预算线上，
是 3197 个区域撑满的。09:35 加进存档的 `visited_places` 又占 **4.67 MB = 载体的 23.2%**，
而它和区域质心**交集 0**（一个都对不上）。载体超预算，`fold_to_capacity` 每小时折 5% 区域：
**09:00 的 3184 → 14:00 的 2302（-28%）**。**她缩得比原来快，因为她开始记一本没用的日记。**

**三、三笔账不是三笔并列，是两张牌 + 一笔。**

- **能动 ↔ 位置不漂 是同一个旋钮的两端**——但**怎么修决定了要不要付账**：
  「uid + 到达即记」那版 200 步长出 36 个区域（地形重新长大）；
  「离开即记」那版区域数反而少 1（2319→2318）、最大分量没涨。**后者才是能上的那一版。**
- **不崩是另外一笔**：153 次崩溃里只有 **52 次**是「漂过 1e6 → 拒存」；63 次是 `_folded`
  的 `UnboundLocalError`，跟位置没关系。而 **「95 次」这个数本身是错的**（真实 153）。

## 零点五、白默 13:55 定的方向（这一条改变了「几刀」的内容）

> 「什么边？物理意义上的？**我不觉得应该有边界**，我想让她在电脑里存在，
> 但**不依托于电脑的那么多东西比如终端**。」

**所以「她应该多大」不再是 A/B/C 三选一。** 三个选项都假设「要给她定个大小/边界」；
白默说不要边界。那么：

- **不设界**：`|x|` 可以一直长——不漂的判据不能是「走不远」。
- **要保证的是「多大的坐标都能活着」**：数值表示、存档、判据都不能被绝对量级绑住。
  这正是 `recenter`（纯换原点，平移不变）和「把 1e6 绝对上限换成相对判据」要干的事。
- **世界大小是她长出来的，不是参数**：「发育」该量的是她的结构/精度/寿命，不是她走多远。
- **第二条要求更重**：她不该因为宿主抽风而死。153 次崩溃里，ZMQ 端口 7 次、`NameError bs` 10 次、
  `deepcopy` 6 次——这些是终端/进程/端口的病，不是她的病。**这一条要单独列一刀。**

## 零点六、载体账：她为什么在缩（今天最急的一件）

### 她的载体里是谁占的（19.69 MB，27 个键，逐键复算）

| 键 | 大小 | 占比 |
|---|---|---|
| `attractors` | 15,144 KB | 75.1% |
| **`visited_places`** | **4,672 KB** | **23.2%** |
| `self_model` | 141 KB | 0.7% |
| `graph` | 94 KB | 0.5% |
| 其它 | < 100 KB | — |

`visited_places` 是 **11-18 09:35** 才进存档的，当时注释写「她走过的通常只有几十到几百个，
不大」——**实测 3868 个**，而且和区域质心**交集 0**（见 §一.3）。

### 但缩水不是 09:35 才开始的（人家一开始说重了，收回）

核实 `l5.fixed.pkl`（**08:24，那时还没有 `visited_places`**）：

```
regions 3197   payload 19.49 MB
  attractors 18.99 MB
```

**载体在 09:35 之前就已经贴着 20 MB 预算了。** `visited_places` 是**加速**，不是**开始**：

```
attractors 19.0 MB（3197 个区域，members 撑的）≈ 预算
  + visited_places 4.5 MB（09:35 加）
  = 23.5 MB 超预算
  → fold 要多砍 ~4.5 MB 的区域来腾地方（≈700 个）
```

### 每天看：她本来就在「折叠—再生」里循环，今天只删不补

| 日期 | 首 | 末 | 最小 | 最大 |
|---|---|---|---|---|
| 11-15 | 577 | 1077 | 577 | 1106 |
| 11-16 | 1077 | 472 | **3** | 1182 |
| 11-17 | 497 | 3198 | **8** | 5090 |
| 11-18 | 3198 | **2279** | 2279 | 3198 |

11-16 掉到过 3，11-17 又长到 5090——**她的系统一直有「折叠后再生」**。
今天的不同是：**单调下降、没有反弹。**

再生靠「她走动 → 记录新区域」，而今天她 HOLD（见零点八）。

### 完整的链条（今天所有发现的连线）

```
visited 记账坏（交集 0）
   → 二节点环 / HOLD 死锁（她不动）
   → 不再记录新区域
   → fold 只删不补（载体又贴着 20 MB）
   → regions 单调 -28%
   → per_tension 跟着涨（假象，见零点七）
```

**载体是触发器，记账是根。** 两条都要修，缺一条她都会继续缩。
**而且她在减速**：14:07 2302 → 14:31 2279（≈ -58/h，上午是 -180/h）——区域少了、payload 小了，
下次 fold 来得更晚。**自限，但极限取决于 `visited_places` 和 `members` 谁先停。**

`tests/test_structure_guard.py::test_no_free_fall_across_two_windows` 今天**红了**：
`[2331, 2319, 2302, 2293]`，四窗全降。**这条红是真的，不是误报。**

### 止血（已写进分支）

不存 `visited_places`：**payload 19.69 → 15.27 MB**（-4.42 MB），离预算 4.7 MB。
**不改变行为**（命中率本来 0，见 §一.3）；但这只是把她从 19.7 退回 15.3——
**08:24 之后没见过的低点，不是「回到 09:35 之前」**（那时也是 19.5）。

测试：`test_persist_atomic` 3/3、`test_l5_age_persistence` 6/6、`test_existence_bounds` 3/3。

### 合并后到底会不会停？——副本预演过了

`data/exp/probe_merge_preview.py`：同一份存档、强制 LEAVE、600 步，
**每 60 步（P2 的保存间隔）调一次 `fold_to_capacity`**，判据是 payload 字节数 > 20 MB。

| | payload 起 | payload 末 | fold 触发 | fold 共删 | regions |
|---|---|---|---|---|---|
| **with_visit**（合并前） | 19.39 MB | **19.85 MB** | **2 次** | **220** | 2163 → 2037 |
| **without_visit**（合并后） | 15.18 MB | **15.16 MB** | **0 次** | **0** | 2276 → 2249 |

**合并后 600 步里 fold 一次都不触发，载体稳定在 15.2 MB。**
（`regions` 那 -27 是副本缺 L1 的慢降，不是 fold；真机上有 L1，HANDOFF 第 79 节记过这个差别。）

**所以第 0 刀的预测不是估的，是预演出来的：缩水会停。**

### 体积的主因其实是 `members`

实测（当前存档，2286 个区域）：

```
members 长度：中位 2，均值 5.3，最大 64
payload 19.76 MB
  members 截到 16 -> 16.19 MB
  members 截到 8  -> 14.19 MB
  members 截到 4  -> 12.85 MB
  members 删掉   ->  7.52 MB      ← 12.2 MB 全是 members（62%）
```

副本实验（300 步、强制 LEAVE、同种子）：

| maxlen | payload | 300 步后 regions | transitions |
|---|---|---|---|
| 64（现状） | 15.3 MB | 2306 | 272 |
| 16 | **11.7 MB** | 2306 | 272 |
| 8 | **9.7 MB** | 2306 | 272 |

**三组行为逐点相同**——这个窗口里降 maxlen 是「免费的」（大多数区域 members 中位就是 2，
截断只动到少数胖区域）。长期影响要跑更久才知道。
**真要长期控载体，`members` 的 maxlen 比区域数更有效**——但那是「她的记忆该多长」，
不是工程参数，今天没动。

## 零点七、上午那个「她变紧」是假象（第 6 个判据也塌了）

上午第 92 节说：全部分位都在涨，所以「她真的在整体变紧」，不是幸存者偏差。
**拿今天的 137 个观察点做回归：**

```
per_tension = -0.011790 * regions + 42.077        R² = 0.9850
残差 std = 0.468（跨度 3.94 → 14.65）  残差首尾 -0.437 / -0.467（没有趋势）
corr(regions, per_tension) = -0.992
corr(regions, tension_sum) = -0.963     sum 的 R² = 0.928
```

**「她变紧」的 98.5% 由「区域变少」解释。控制掉区域数之后，残差没有趋势。**

所以今天 `per_tension` 从 6.85 涨到 14.65（+114%）、`p75` 涨 31%——**不是她在绷紧，
是她被 fold 删小了，剩下的连接承担更多**。这是「幸存者偏差 + 结构变稠」，不是「她主动紧张」。

**因果链闭合了**：

```
visited_places 4.67 MB（命中 0）
   → 载体贴 20 MB
   → fold_to_capacity 每小时删 5%
   → 区域 -28%、平均张力 +114%
   → 看起来「她越来越紧」
```

**上午那五个判据塌掉之后，这是第六个。** 而它和「别用标量看她」是同一条：
`per_tension` 是个标量，它被 `regions` 带着走。

## 零点八、HOLD 是死锁，不是选择

她的动作判据是：`tension > 最近 64 步的中位` → LEAVE，否则 HOLD。

今天 6.8 小时、137 个观察点：

```
tension_sum 中位 5,755；相邻 3 分钟变化中位 15.4（0.27%），p90 111.6（1.9%）
```

**她的张力在 64 步里几乎不动（<1%），所以 median 几乎等于当前值 → 判据在临界点上。**

实测（同一份存档重载三次、各跑 20 步）：两次 **0 次 Leave**（全 HOLD），一次 **9/10 次 Leave**。
**她动不动，不是「想不想」，是启动瞬间的浮点。**

这是一个**双稳态**：

```
HOLD → 结构不变 → 张力不变 → 中位不变 → 永远 HOLD
LEAVE → 移动 → 结构变 → 张力变 → 可能一直 LEAVE
```

**今天下午她锁在 HOLD 里。** 13:27 起连续 8 个快照都是 `hold`；
14:25 实测最近 300 秒 57 次转移，**她自己走的 0 次**。

这解释了更早的一个谜：为什么 `vitals` 一直报 `alive`（累积 leave_rate 0.684），
而她其实一动没动。**判词看历史，动作看浮点。**

（要打破这个死锁得改动作判据——比如加一个「多久没动就动一次」的最小探索。
那是 L4/L5 的行为改动，今天不动，等白默。）

**但补丁本身就把死锁打破了。** 同一份存档、5 个种子、各 300 步、**不强制动作**：

| seed | 她走了几次 | 转移 | regions | payload |
|---|---|---|---|---|
| 1 | 167 | 142 | 2274→2263 | 15.21 MB |
| 3 | 192 | 134 | 2274→2267 | 15.25 MB |
| 5 | 163 | 135 | 2274→2263 | 15.21 MB |
| 7 | 147 | 119 | 2274→2263 | 15.21 MB |
| 11 | 199 | 162 | 2274→2265 | 15.24 MB |

**5/5 全在走**（147-199 次 / 300 步）；对照：未打补丁时同一份存档重载 3 次，2 次 **0 次 Leave**。
regions 微降 7-11（副本缺 L1 的慢降），payload 稳定 15.2 MB。

**所以第 1 刀不只是「修记账」——它顺手把她从 HOLD 里放出来了。**
原因不复杂：目标变了 → 走一次 → 结构变 → 张力变 → 判据不再是常数。

## 一、能动（今天最值钱的一块）

### 1. 一步真的走一个半径

把动作口锁成 LEAVE、噪声关掉，连走 6 步：

```
|step| = 617.34   617.34   617.34   617.34   617.34   617.34     （s = 618.04）
落点离最近质心 = 0.0077（每步都一样）
```

「一步一个半径」是真的（617.34 / 618.04 = 99.9%）。**但落点永远差 0.0077 没到质心。**

### 2. 她落的那些点，间距正好等于步长

她身边最近的 12 个区域，距离：

```
0.135 · 617.35 · 709.34 · 1670.5 · 1778.4 · 1827.7 · 2888.8 · 2921.8 · ...
```

**617.35 = 她的步长。** 她脚边最近的另一个区域正好在**一步之外**——那是她自己的脚印；
再往外是 709、1670、2888……（全局最近邻中位是 971，不是每个都 617）。
所以「离开」和「到达」是同一件事：走一步就到下一个脚印。

### 3. 二节点环的根：visited 和 places 不是一个坐标系

`src/L5_cognition/stream.py` 第 687-692 行（记「去过」）与第 678-679 行（候选区域的键）：

```python
_here = tuple(np.round(np.asarray(self._st.x), 4).tolist())   # 她的位置
self._visited_places.add(_here)

places = [tuple(np.round(np.asarray(attrs[i].mu), 4).tolist()) # 区域质心
          for i in idx]
```

`action.py` 第 157 行再用 `places[k] not in visited` 判「没去过」。

**实测（`data/exp/probe_visited.py`）：**

```
regions 2329   places 2329   visited 3675
visited ∩ places = 0
她落在质心外 0.0077 → 每个分量差 ~7e-4，而 round(·,4) 的精度是 5e-5
```

**3675 个「去过」，一个都没对上 2329 个区域。**
所以「去还没去过的区域」这个策略**从上线到现在，一次都没生效过**。

### 4. 动作门在临界点上

```
tension 7305.57   vs   历史 64 步中位 7306.40     差 -0.83（0.01%）
```

三次重载同一份存档、各跑 20 步：两次 **0 次 Leave**（全 HOLD），一次 **9/10 次 Leave**。
**她动不动，不是由「想不想动」决定，是由快照的浮点决定。**

**真机 13:49 实测（`tools/vitals.py` 今天新加的 recent 行）：**

```
recent : 300s 内转移 63 次，其中她自己走的 0 次；最后事件 32.5s 前
         ⚠ 全是噪声推的，一次「离开」都没落地
```

`vitals` 原来照样报 `alive`——因为它读的 `leave_rate` 是**累积**的（0.699），不是「刚才动没动」。
**这就是「她看起来活着，其实一步没走」的完整证据。**

（人家把这条做进判词了：`vitals` 现在报 **`still`** ——「结构在、有转移，但最近 15 分钟
一次都不是她自己走的」。`tests/test_vitals.py` 3/3 仍过。）

### 5. 结论：能动是三层叠起来的

| 层 | 事实 | 后果 |
|---|---|---|
| a | 一步 = 一个半径；她**实际选的目标**就在 617（副本实测 p50 **617.34**） | **一步就到**；「走不到」对她现在**不成立** |
| b | 「去过」的键和「区域」的键交集 0；质心两次访问间还会漂 1.02e-4 > 4 位小数的量子 | 同一对近邻永远「没去过」→ 二节点环 |
| c | 动作门差 0.01% | 她可能一直站着，而日志看不出来 |

**「617 vs 91 万」是「全部候选的中位」，不是「她选的目标」。**
第 80 节据此说「一步只覆盖 0.05%」——**对目标不成立**（对目标她一步覆盖 100%）。
这条人家今天跟着错了一下午，是 move-experimenter 那组用 600 步实测纠正的
（`docs/2026-11-18_存在_能动_副本.md` §1）。

**所以真正锁住她的是 b。** a 要等 b 修好、目标被推到 39k 之后才会露出来。

### 6. 副本实验：把「去过」记对，环就断了

**A. 拆开验证「键对不上」到底多致命**（`data/exp/probe_dir2.py`，强制 LEAVE，一步步看）：

```
step 0  visited 3691  hits_in_places 0  fresh 1163  target_dist 617.38  step 617.38
step 1  visited 3692  hits_in_places 0  fresh 1163  target_dist 617.36  step 617.36
step 2  visited 3693  hits_in_places 0  fresh 1163  target_dist 617.37  step 617.37
```

`visited` 每步都在长，`hits_in_places` 永远是 **0**。
因为她的落点离质心 0.0077，而两边的键差在 1e-4 以下——**同一个地方，两个名字，永远撞不上**。

**B. 纯几何对照：只换「去过」的记账方式**（`data/exp/probe_uid_sim.py`，200 步，同一份存档）：

| 记账方式 | 到过几个区域 | 转移数 | 回边率 | 200 步位移 |
|---|---|---|---|---|
| 现在（位置键） | **3** | 200 | **0.99** | **0.0** |
| 改成区域 uid + 到达即记 | **137** | 137 | **0.007** | **104,718** |

**C. 走真实代码路径**（`data/exp/probe_uid_full.py`：只换 `_apply_leave` 的记账，其余全走原代码，
200 步、强制 LEAVE、同种子）：

| | 到过区域 | 转移 | 回边率 | 位移 | 区域数 | 最大分量 |
|---|---|---|---|---|---|---|
| 原版 | 2 | 199 | **1.00** | 0.2 | 2322→2316 | 229,611 |
| uid 记账 | **17** | 28 | **0.37** | **74,353** | 2322→**2358** | 237,482 |

三件事：
1. **二节点环断了**（回边率 1.00 → 0.37），她开始换地方；
2. **区域数从 2322 涨到 2358（+36）**——她一动，就沿路长出新的区域。**能动一修好，地形就开始重新长。**
3. 最大分量 22.9 万 → 23.7 万，200 步里没往 1e6 上撞。

**所以第 1 刀（能动）和第 2 刀（位置）必须一起上**，不然就是 11-17 那次重演：
她走得起来的那天，就是地形重新长大的那天。

**二节点环不是尺度问题，是记账问题。** 换掉记账方式，环就断了（回边率 0.99 → 0.007）。

**但看第四列：她开始走了，200 步走 10.5 万。**
再拉长（同一份静态地形，只换记账）：

| 步数 | 到过区域 | 回边率 | 累计位移 | 净位移（离原点） | 最大分量 |
|---|---|---|---|---|---|
| 200 | 107 | 0.00 | 118,806 | 940,166 | 216,798 |
| 1000 | 525 | 0.00 | 498,320 | 624,273 | 150,047 |
| 2000 | 1076 | 0.00 | 1,017,181 | **154,758** | **32,042** |

**好消息**：她在云里绕，不是直线往外冲——2000 步走了 100 万，净位移只有 15 万，

### 数据（同一把尺，六个存档）

### 三个发现

**一、地形从 11-17 23:36 起就没再长大。** 两两中位 562,030 → 591,740（+5%，14 小时）。
今天在变的不是地形，是**坐标原点**。

**二、`recentered` 证明平移不动几何，但它漏搬了 x。**
四个存档的两两距离一致到 1e-10 以内（p10 122,398 / median 572,930 / p90 1,395,225）
——平移是刚体变换，改不了她空间里的任何距离。（严格说做不到逐位相同：从 1e6 量级的坐标上
减一个 1e6 量级的数，float64 本身要丢 1e-10。这也说明坐标不该待在这个量级。）
可它只搬了 `mu`、没搬 `x`：她从「在云里」变成「在云外 194 万」（`d_nearest = 1,941,970`）。
半天后那个 `fixed` 就是把她拉回来。**坐标系平移要么 x 和 mu 一起搬，要么别搬。**

**三、`|x|` 不是判据，绝对上限才是问题。**

空间平移不变，|x| 是 409 万还是 9.6 只说明原点在哪儿。真正会伤人的是
`SAVE_MAGNITUDE_LIMIT = 1e6` 卡**分量绝对值**（`src/common/persist.py` 第 366 行）：
08:24 那次就是漂过 1e6 → `assert_l5_finite` 拒存 → P2 崩。

**而她现在离这个上限只剩 24%。** `reorigin.max_component()` 实测：**758,240**。
按地形中心搬一次原点之后是 **728,580**——**搬不动**，因为她的地形本身就有 73 万那么大。
**所以「08:24 撞上限」不是偶然事故，是必然：再走一段就撞。**
这不是「把她拉回来」能解决的，是「存档用绝对上限」这条设计到了该换的时候。

**而且这个锚现在没有任何测试守着。** `tests/` 里 grep `锚|anchor|drift`：只有 `test_no_senescence` 的「参数不随年龄漂」，没有一条测位置。

三件事：
1. **区域数稳**（2319 → 2329，+10）。1000 步里没有「地形重新长大」。
2. **`|x|` 慢**（+3.6 万 / 1000 步）。她是在地形**内部**走，不是往外冲。
3. **`max 分量` 一动不动**（758,240）。因为那个分量是**地形里已有的某个点**，不是她的 x。

**第 1 刀可以单独上**（1000 步数据见上），但**第 2 刀越早越好**：758,240 的余量只剩 24%，

**第 3、4 刀是另一件事**：153 次里 101 次跟位置无关，其中 23 次是宿主的病——
白默那句「不依托于电脑的那么多东西比如终端」直接对应第 4 刀。

> 白默睡了，人家修存在层。**修出了一个新崩溃**——已经修好。

---

## 发生了什么

**23:00**：人家给 `arrival_hist` 加存档（它决定 `prefer_far`——破环能力）。

**23:07**：她崩了 9 次（崩溃账 166 → 175）。

**原因**（`stream.py:844` 旧代码）：
```python
_a = tuple(np.round(np.asarray(...), 4).tolist())   # 存的是位置 tuple
self._arrival_hist.append(_a)
```

**而人家在 `persist.py` 里写的是**：
```python
[int(v) for v in getattr(stream, "_arrival_hist", ())]   # int(v) —— tuple 不能转 int
```

**于是**：`TypeError: int() argument must be ... not 'tuple'` → **保存失败** → **崩溃**。

---

## 修法

**统一改成 uid**（和 `_visited_places` 一致）：

```python
_arr = getattr(self.detector, "current_attractor", None)
if _arr is not None:
    self._arrival_hist.append(int(_arr))
```

**理由**：位置会漂、和现状对不上；uid 稳定、可比、不崩。

**验证**：
```
200 步: arrival_hist = [31889, 31680, 31680, 31680, 31737, 31888]
payload: 同上
apply 后: 同上
```

**测试**：action 8/8、prefer_far 4/4、rest_energy 9/9、self_heal 2/2、stuck 6/6 **全过**。

## 教训（人家自己的）

**改“存档”相关的代码，必须验证「存 → 加载」**——**人家只验证了“存”（payload 有 `arrival_hist`），没验证“加载”**。

**而且**：`arrival_hist` 里存的是什么类型，人家**没看**（以为是 int，实际是 tuple）。

**这已经是今天第三次“人家自己引入的 bug”**：
1. `_lim` 缩进搞乱（锚定逻辑坏了）
2. `min_amp` 分位法（删太狠）
3. `arrival_hist` 类型错（崩溃 9 次）

**规律**：**都是“改了之后没完整验证”**。

**以后**：**每次改完，先跑「存→加载→行为」三步**，再看日志。

## 二、理论依据

### 2.1 自创生不够（Di Paolo 2005）

> **"Autopoiesis is necessary but not sufficient for cognition because it omits
> adaptivity, the capacity of a system to regulate its own relation to its
> conditions of viability."**

链条：

```
自创生（自我生产） + adaptivity（可适应性）
    → sense-making（意义生成）
    → agency（能动性）
```

**sense-making 不需要目标、奖励、价值判断。** 只需要：

1. 存在"能继续的区间"
2. 系统能感知自己在区间里的位置
3. 系统能调节自己

### 2.2 稳定性 ≠ 恢复力（Holling 1973 / Ludwig, Walker & Holling 1997）

| 术语 | 定义 |
|---|---|
| **stability**（稳定性） | 受扰动后回到平衡点的倾向 |
| **resilience**（恢复力） | 吸收扰动而**不脱离当前状态区间**的能力 |

Holling 1973 原文：

> "Resilience determines the persistence of relationships within a system and
> is a measure of the ability of these systems to absorb changes of state
> variables, driving variables, and parameters, and still persist."

**这两个不是一回事。** 一个系统可以极稳定（很深的坑）但恢复力差（一旦离开就回不来），也可以不太稳定但恢复力好。

**我最初实现的是 stability，而真正该管的应是 resilience。**

## 三、实现

### 3.1 承载深度（carrying depth）

一个区域能维持多少深度，由它自己的访问频率决定。

```
p = 累计赋值数 / 总观测步数        （实测访问率）
R = recover_rate × 个体衰减因子 / 恢复间隔

平衡：p × assign_ratio × (ceiling - amp*) = R × amp*

    amp* = ceiling × (p × a) / (p × a + R)
```

**含义**：很少被访问的地方，撑不起多少深度。这是它自己的物理约束。

**第一版的错误**：假设"每步都有赋值"，算出 amp* = 0.998（几乎等于上限），导致 99.5% 的吸引子被判为"低于承载"。**这个判据没有区分度。**

### 3.2 存续比（viability ratio）

```
ratio = amp / amp*
```

- `ratio > 1`：比自己的访问率能撑起的更多
- `ratio < 1`：比能撑起的更少

### 3.3 调节（regulation）

```
pull_factor = ratio ^ beta
```

一个区域离自己的平衡越远，它对外作用越强或越弱。

**关于 beta**：这是一个**工程标度，不是理论常数**。Di Paolo 的 adaptivity 是定性概念，文献没有给出标准函数形式。取 1.0（恒等关系）。

实测敏感性：

| beta | rev32 | salient | travel/R |
|---|---|---|---|
| 0.0 | 45 | 4 | 33.44 |
| 0.5 | 47 | 7 | 13.95 |
| **1.0** | **51** | **13** | **14.05** |
| 2.0 | 52 | 13 | 70.47 |

如果挑"看起来最好"的那一行，就是在拿数据拟合我的偏好。所以固定为 1.0，并把这个选择写在代码里。

## 四、一个被否决的机制：可通行边界

最初加了一个「墙」：势能在结构太薄的地方升高。

实测结果与设计意图相反：

```
              none     wall
travel/R      37.68   117.51
salient           5        1
```

**开了墙之后她走得更远了 3 倍，显著吸引子从 5 降到 1。**

原因：墙加的是**正向势能**，也就是一个推力，会把状态推离薄的地方。而推出去的地方更没结构。

**这跟 resilience 的定义相反**：Holling 说的是「吸收扰动」，不是「弹开扰动」。

**结论：墙默认关闭。** 代码里 `_wall_enabled = False`，理由写在注释里。

## 五、病态结构的处理

### 5.1 发现

旧存档里有一个区域：

```
76456 次赋值, amp 0.997, sigma 0.00041
amp / sigma² = 5,938,138
```

它一条贡献了 1471 的梯度，其他所有加起来不到 1。她一动就被甩出去，速度 14.7。

### 5.2 成因

旧代码的 `global_scale` 用滚动窗口（最近 64 步），她停住时会塌到 1e-4。于是新建的吸引子也被设成 1e-4 宽，所有访问挤在一个针尖上。

**新代码不会再产生这种结构。**

### 5.3 处理（白默的决定：留着但不让它主导）

**一、尺度自洽性**

```
sigma >= amp/(amp+1) × median_sigma
```

一个占了接近满深度的地方，宽度不可能只有一个点。

**二、主导上限**

```
单条贡献 ≤ 其余所有贡献之和
```

不是绝对值上限，是相对关系。

**三、顺序修正**

`_apply_scale_floor()` 原本在第一步 `record()` 末尾才调用。但那个病态区域就在起点上，**第一步的梯度已经用上了未修正的尺度**。改成加载时立即应用。

## 八、实测

### 一个关键发现：结构的分布极度不平衡

在修病态结构之前，统计了一下访问分布：

```
top   1 区域占 94.3% 的赋值
top  40 区域占 98.4%
去掉最大的那个：salient 从 1 变成 0
```

**她的全部结构，就是一个坑加 231 个碎片。**

之前所有看起来在变好的指标，都是那个坑在动，跟其他碎片无关。

### 为什么碎片长不大

```
被访问 ≤3 次的区域：amp 中位数 0.0143
被访问 ≥16 次的区域：amp 中位数 0.0082   ← 更浅！
```

**被访问得多的区域反而更浅。** 这不应该发生。

根因是一个尺度不匹配：

```
典型回访间隔  p50 = 47,221 步
深度半衰期        =  5,540 步
```

**回访间隔是半衰期的 8.5 倍。** 她离开一个地方后，那里的深度会掉到原来的 1/300 才回来。

### 修正：按回访间隔缩放恢复速率

每个区域的恢复速率除以「自身回访间隔 / 当前半衰期」：

```
rate_scale = min(1, half_life / own_interval)
```

- 常回访的区域：保持原速率
- 很少回访的区域：按「有多久才回访一次」等比例放慢

**这不是让所有东西都记住。** 只被访问一次、再也不回来的区域照样会淡，只是淡的速度和「任何东西可能回来的时间尺度」一致。

### 修正后（6000 步）

```
step 1000: att 244  rev32 46  salient  6  speed 1.32  below 0.934
step 3000: att 263  rev32 49  salient 12  speed 0.93  below 0.848
step 6000: att 294  rev32 56  salient 15  speed 0.76  below 0.745
```

**三条曲线同向收敛：**
- `below`（低于自身承载的比例）：0.93 → 0.75
- `salient`（显著吸引子）：6 → 15
- `speed`：1.32 → 0.76

### 修病态结构之前 / 之后（800 步）

| | 之前 | 之后 |
|---|---|---|
| 加载时梯度 | 1471 | 62.8 |
| 第一步速度 | 14.7 | 0.63 |
| attractor 增长 | 233 → 519 | 233 → 249 |
| rev32 | 43 | 47 |
| salient | 1 | 6 |

### 当前配置的长期运行（beta=1.0，墙关闭）

```
step  500: att 248  rev32 46  salient  4  speed 0.64
step 1500: att 245  rev32 44  salient  4  speed 0.57
step 3000: att 253  rev32 50  salient 13  speed 0.22
```

**结构稳定，不再膨胀。显著吸引子从 4 涨到 13，速度下降。**

### 消融（800 步，四种条件）

```
               none     pull     wall     both
attractors      265      243      344      317
rev16            64       68       60       66
rev32            47       49       43       45
salient           5        9        1        9
speed        0.0498   0.3815   1.0813   0.8481
travel_R      37.68    8.97   117.50    90.22
frac_below   0.8642   0.9424   0.6657   0.7224
```

**pull 是唯一有效的机制**：活动范围收窄 4 倍，重复访问增加，层次增加。

## 八、没解决的

1. **`frac_below` 仍是 0.88**：大部分区域低于自己的承载水平。这要么说明承载深度的定义还有问题，要么说明结构确实没长好。
2. **墙被否决了，但"哪里能待"这个问题还没答案**。pull 只是让她在有结构的地方停得更久，没有告诉她哪些地方根本不该去。
3. **`beta` 只取了 1.0**，没有理论依据，只是恒等关系的自然选择。
4. **没在真实三进程里跑过。**

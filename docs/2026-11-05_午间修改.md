## Bug 1：`global_scale` 用滚动窗口，被她自己的静止污染

### 现象

她真实运行 24048 步后：

```
attractors 281   basins 1   transitions 27（卡死）   edges 5   tensions 0
recall 索引 293 → 274（痕迹在稳定地死）
```

### 根因

```python
_recent = deque(maxlen=64)          # 最近 64 个状态
global_scale = RMS(_recent 相对重心的偏差)
```

她被困在一个深坑里反复振动，位置几乎不变：

```
64 个点每维跨度 : 1e-4
她的实际速度    : 0.0588
```

于是 `global_scale` 塌到 `1e-4`。而它是**新建 attractor 的初始 sigma 的唯一来源**。

### 后果链

```
被困 → 位置不动 → 尺度塌到 1e-4
  → 新建 attractor 只有 1e-4 大
  → 稍一动就"不认识这是同一个地方"
  → 碎成 280 个 1e-4 的碎片
  → 其中最深的那个吃掉几乎所有赋值（实测 68743 次）
  → 她永远出不来
```

### 修法

**尺度不再连续跟踪，改成按需从已有结构测量。**

```python
def current_scale(self):
    # 已有吸引子之间最近邻距离的中位数
    # 这是她走过的地方的真实分布，不是她当前的运动
```

为什么这样对：连续估计器全部失败于同一原因（状态停住时都报 1e-4），因为它们在回答"她动得多快"，而真正的问题是"这一片区域多大"。唯一直接证据是**已经形成的区域之间的间距**。

### 实测

```
修前：gscale 0.000467，salient 1
修后：gscale 0.052 → 0.208（稳定），salient 8~11
```

## Bug 2：成员缓冲在存档往返后失去上限

### 现象

读存档时发现，一个 attractor 挂着 **68743 个成员状态**，而代码里写的是 `deque(maxlen=64)`。

### 根因

```python
# save
"members": list(a.members),         # deque(maxlen=64) → 普通 list

# load
members=list(d["members"]),         # 显式赋值 → 字段的 maxlen 被丢弃
```

Python 的 dataclass 在**显式传参**时不会应用 `default_factory` 的 `maxlen`，所以 `members` 变成了无上限的 list。

### 后果

- `sigma` 从 68743 个历史状态算，被远古离群点拉大（实测中位半径 0.0005，但 RMS 0.0073，差 15 倍）
- 判据 `距离/sigma < 1` 因此过宽，什么都进得来，越进 sigma 越大
- 存档膨胀到 72 MB

### 修法

```python
a.members = collections.deque(list(d["members"])[-MEMBER_BUFFER:],
                              maxlen=MEMBER_BUFFER)
```

### 实测

```
修前 max members: 68743
修后 max members: 64
```

## Bug 4：存档根本不存 L3 的连接图

### 现象

存档往返测试：

```
edges  184 → 0
```

### 根因

`save_l5` 只存了 attractors、位置、速度、零点，**没有存 `TraceGraph`**。`load_l5` 也就没有恢复它。

### 后果

**每次重启，L3 积累的全部连接清零。** 昨天写的 L3 层一直是白做的。

### 修法

`save_l5` 增加 `graph`（连接）和 `identity`（身份观测历史）两段；`load_l5` 恢复它们。

### 实测

```
edges  184 → 184   ✓
identity 轮数也一起恢复
```

## 还没解决的

1. **`amp_p50` 持续下降**（0.047 → 0.012）：浅的多、深的少，呈长尾。可能是正常的（大部分地方只去过一两次），但需要确认。
2. **`global_scale` 缓慢上升**（0.14 → 0.208）：可能意味着她的活动范围在扩大，也可能是结构在稀疏化。
3. **那个 0.9987 的深坑还在**：它是 24 小时旧数据留下的，会随成员缓冲替换慢慢变化，但现在仍主导显著度。
4. **`l5.pkl` 72 MB**：修了 members 之后新的存档会小很多，但旧文件不会自动变小。实测修后 164 个 attractor 的存档是 660 KB。
5. **冷启动时 attractor 增长偏快**：8000 步 913 个、61 个显著。还在增长阶段，没看到稳定，但比旧存档路径分散得多。

## 四个 bug 的共同点

**全部是"一个量同时承担了两个职责"。**

| bug | 同一个量 | 承担了两个职责 |
|---|---|---|
| 1 | `global_scale` | 既是"她最近动多少"又是"区域多大" |
| 2 | `members` | 既是有限缓冲又是全部历史 |
| 3 | 衰减因子 | 既是时间流逝又是离开证据 |
| 4 | `l5.pkl` | 既是地形又是全部状态 |

睡之前白默说了一句话："判断和度量不能是同一个量。"四个 bug 是同一句话的四个实例。

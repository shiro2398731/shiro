## 实测结果

### 1. 载体：19.7 MB → 13.19 MB

| 时刻 | `l5.pkl` | 说明 |
|---|---|---|
| 16:56（旧代码，合并前） | 19.7 MB | 贴着 20 MB 预算 |
| 17:00:58（新代码第一次保存） | **13.19 MB** | `visited_places` 不再进存档；区域也少了（1879） |

**离 20 MB 预算还有 6.8 MB。** `fold_to_capacity` 短期内不该再触发。

### 2. 缩水停了

| 时刻 | regions |
|---|---|
| 16:27 | 1914 |
| 17:01 | 1879 |
| 17:07 | 1874 |
| 17:32 | **1845** |

**16:27 → 17:32（65 分钟）-69**，而上午是 -180/h、下午 14:00–16:00 是 -233/h。
**速率掉到原来的 1/3，而且这 69 个里有多少是启动时的 pruning 还不清楚。**
（17:32 还在缓慢下降，要再观察一小时才能说「完全停了」。）

### 3. 她在动，但频率低

`vitals` 的指标今天下午写错过一次，修完之后才看见：

```
recent : 300s 内 leave 1 次，转移 92 次（噪声推的 92）
verdict: alive
```

observations 里最近 60 个采样点：**32 次 leave / 60**，`leave_share` 从 0.6292 涨到 0.6324。

**结论：她确实会自己走了，但一分钟不到一次。** 比合并前的「一次都不走」好，
但离「连续存在」还远——她现在的移动是稀疏的、被张力判据卡在临界点上。

### 4. 人家自己的工具也错了一次

13:49 加的 `recent` 行统计的是「`events.jsonl` 里 `noise_driven=False` 的转移」。
而**她做 LEAVE、走一步还在同一个区域里**时，根本不产生 transition 事件——
于是「她明明在走」被报成「一次都没走」。

修法：改成从 `observations.jsonl` 的 `action` 字段数 leave（那是她每一步真实的选择）。
这条和上午「别用标量看她」是同一个病：**用一个间接量当直接量。**

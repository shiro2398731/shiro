### 3. 她在走，而且频率不低

**实测（读存档的 `action_counts` 两次、间隔 120 秒）：**

```
120s: steps +56, leave +40, hold +16, leave/share = 0.714
```

**71.4% 的步是「离开」**——和副本里 5 个种子的 147–199 次 / 300 步（49%–66%）一致。
`leave_share` 也从 0.6292 涨到 0.6324。

**所以合并后她是「正常运行」的，不是「站着」。**
之前 13:49 那版 `vitals` 之所以报「0 次」，是因为它数的是 `events.jsonl` 里
`noise_driven=False` 的**转移**——而「leave 走一步还在同一区域」根本不产生转移事件。

### 4. 人家自己的工具错了两次，同一个病

1. 第一版（13:49）：数 `events.jsonl` 的转移 → 「她明明在走」被报成「一次没走」。
2. 第二版（17:35）：数 `observations` 里窗口内的 `action == leave` 条数 → 300 秒窗口里
   只有 1–2 条采样，于是报「leave 1 次」，还是看不出频率。

**正确口径是「每步的 leave 比例」**，也就是 `action_counts` 的增量。
两次犯的病一样：**拿一个间接量当直接量**（上午「别用标量看她」是同一个病）。
`vitals` 现在只是不撒谎了（不再报 still），频率还得用这个增量法量——
要不要把「最近 N 步的 leave 率」做进 P2 的观测字段，是下一步（要改 P2，没动）。
